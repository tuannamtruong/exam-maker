# Scenario
A company has a mission-critical, public-facing containerized application running on an EKS cluster with microservices architecture. There is a requirement to implement a fully managed centralized application logging solution that automatically collects metrics and application logs. The company also requires a dashboard to easily monitor the application metrics.

# Question
Which solution meets the requirements with the LEAST amount of operational overhead?

# Options
1. Install and set up the CloudWatch agent on the EKS cluster to collect the metrics. Use the CloudWatch dashboard to view the application logs.
2. Set up and configure Managed Service for Prometheus metrics collection for the EKS cluster by installing the Prometheus agent on all EKS pods. Launch a dashboard in Managed Grafana to visualize metrics and logs in EKS.
3. Use CloudWatch Container Insights with the EKS cluster. Use the CloudWatch dashboard to view the application logs and metrics.

# Explanation
Use CloudWatch Container Insights to collect, aggregate, and summarize metrics and logs from your containerized applications and microservices. Container Insights is available for ECS, EKS, and Kubernetes platforms on EC2. Container Insights supports collecting metrics from clusters deployed on AWS Fargate for both ECS and EKS.

Container Insights collects data as performance log events using embedded metric format. These performance log events are entries that use a structured JSON schema that enables high-cardinality data to be ingested and stored at scale. From this data, CloudWatch creates aggregated metrics at the cluster, node, pod, task, and service level as CloudWatch metrics.

The metrics that Container Insights collects are available in CloudWatch automatic dashboards, and are also viewable in the Metrics section of the CloudWatch console. Metrics are not visible until the container tasks have been running for some time.

1. Even though using CloudWatch agent can collect metrics and application logs from an EKS Cluster, it requires some operational overhead because the CloudWatch agent has to be manually configured to collect the application logs from /var/log/containers directory on each node. Also, using a CloudWatch Dashboard does not provide the same level of granularity and aggregation as CloudWatch Container Insights.
2. Although Managed Service for Prometheus is a fully managed solution, you still cannot directly use the Prometheus agent with EKS without integrating it first with an CloudWatch agent. Moreover, launching a dashboard in Managed Grafana only adds operational overhead, which is explicitly dissuaded in the requirements.
