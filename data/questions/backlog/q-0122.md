# Scenario
Web Application Firewall logs are sent to the tdojo-waf-logs log group in CloudWatch Logs.
The organization wants to set up alerts for sudden changes in blocked traffic patterns while ignoring other WAF log behavior changes. Additionally, the organization plans to fine-tune Web Application Firewall rules.

Alerts should be delivered via an SNS topic to which a DevOps engineer is subscribed.

# Question
Which?

# Options
1. Set up GuardDuty to monitor WAF logs for threats. Configure it to trigger a CloudWatch alarm for blocked traffic findings, which will send notifications to an SNS topic for the DevOps engineer. Use an SNS subscription filter policy to ensure only relevant blocked traffic alerts are sent.
2. Use EventBridge to monitor WAF logs in the tdojo-waf-logs group. Set up a rule to detect spikes in blocked requests and trigger a Step Functions workflow for evaluation. Send a notification to the DevOps engineer through the SNS topic.
3. Configure a CloudWatch Logs metric filter to capture blocked requests from the tdojo-waf-logs log group and create a custom metric. Use CloudWatch Anomaly Detection to identify unusual patterns and set up an alarm to notify the DevOps engineer via an SNS topic.

# Explanation
CloudWatch Logs metric filter can capture blocked requests within the tdojo-waf-logs log group and create a custom metric based on patterns of blocked traffic. Subsequently, CloudWatch Anomaly Detection analyzes this custom metric to identify unusual patterns in blocked traffic. By setting up a CloudWatch Alarm on the anomaly detection metric, the organization can receive alerts when there are significant deviations in the blocked traffic.

1. GuardDuty is primarily designed to detect security threats like unauthorized access, malware, or compromised resources. It does not provide direct anomaly detection on Web Application Firewall (WAF) logs or focus on blocked traffic patterns.
2. EventBridge only works by defining rules to detect specific log patterns or spikes. While it can monitor spikes in blocked requests, it lacks anomaly detection capabilities that analyze traffic over time and establish a baseline. Additionally, adding a Step Functions workflow adds unnecessary complexity to the solution. Step Functions are better suited for orchestrating long-running workflows, not real-time anomaly detection and alerting.
