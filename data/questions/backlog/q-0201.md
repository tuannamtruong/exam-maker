# Scenario
The networking team already manages shared networking resources (VPC and subnets) with CloudFormation and exports them.

A DevOps engineer needs to automate creation of many identical development environments. The solution must:

reuse the existing networking infrastructure
create consistent environments
be easy to update as infrastructure grows

# Options
1. Use Fn::ImportValue intrinsic functions in the Resources section of the template to retrieve Virtual Private Cloud (VPC) and subnet values. Use CloudFormation StackSets for the development environments, using the Count input parameter to indicate the number of environments needed. Use the UpdateStackSet command to update existing development environments.
2. Use nested stacks to define common infrastructure components. To access the exported values, use TemplateURL to reference the networking team's template. To retrieve Virtual Private Cloud (VPC) and subnet values, use Fn::ImportValue intrinsic functions in the Parameters section of the root template. Use the CreateChangeSet and ExecuteChangeSet commands to update existing development environments.
3. Use nested stacks to define common infrastructure components. Use Fn::ImportValue intrinsic functions with the resources of the nested stack to retrieve Virtual Private Cloud (VPC) and subnet values. Use the CreateChangeSet and ExecuteChangeSet commands to update existing development environments.
4. Use Fn::ImportValue intrinsic functions in the Parameters section of the root template to retrieve Virtual Private Cloud (VPC) and subnet values. Define the development resources in the order they need to be created in the CloudFormation nested stacks. Use the CreateChangeSet and ExecuteChangeSet commands to update existing development environments.

# Explanation
Nested stacks contain reusable components (ALB, Auto Scaling, DynamoDB, security groups, etc.).
Shared infrastructure such as the VPC is imported using Fn::ImportValue.
Future updates are performed using CloudFormation Change Sets.

1. Count input parameter: not real
2. TemplateURL is only used to reference a nested stack template stored in S3. It does not reference another deployed stack. The networking stack already exists. To consume its outputs you use Fn::ImportValue.
4. Parameters:
    VpcId:
        Default:
            !ImportValue SharedVpc

is not how CloudFormation works.

Fn::ImportValue belongs where a resource property requires the value:

Resources:
    SecurityGroup:
        Properties:
            VpcId: !ImportValue SharedVpc
