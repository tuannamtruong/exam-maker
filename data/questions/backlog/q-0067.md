# Scenario
An analytics web portal processes data using an EMR cluster with an ASG of EC2 instances. After three months, Trusted Advisor recommended terminating underutilized EMR instances. It was found that no scale-down parameters were set, resulting in high billing costs.

To prevent this issue, frequent notifications of Trusted Advisor recommendations are required for timely action.

# Question
Which of the following solutions can help achieve this? (Select THREE.)

# Options
1. Write a Lambda function that runs daily to refresh Trusted Advisor via API and then publish a message to an SNS Topic to notify the subscribers based on the results.
2. Create an EventBridge to monitor changes in Trusted Advisor checks. Set a trigger in SES for sending email notifications.
3. Create an EventBridge rule that monitors changes in the Trusted Advisor check status. Set a trigger in SNS for sending email notifications.
4. Write a Lambda function that runs daily to refresh Trusted Advisor changes via API and send results to CloudWatch Logs. Create a CloudWatch Log metric and have it send an alarm notification when it is triggered.
5. Enable the built-in EventBridge notification feature that scans changes in the Trusted Advisor check result. Send notifications automatically to the account owner.
6. Enable the built-in Trusted Advisor notification feature to automatically receive notification emails, which include the summary of savings estimates along with Trusted Advisor check results.

# Explanation
The demand is "frequent notifications".

2. it is just partially correct since the integration for sending email notifications should use SNS, not SES.
5. there are simply no automatic checks on EventBridge for Trusted Advisor in the first place. You need to manually configure those rules and have them trigger notifications to you.
6. Although this is a viable solution, the notification will be sent on a weekly basis only, which can already incur a lot of costs by the time it is notified.
