# Scenario
Oracle RAC database on their on-premises network which they want to migrate to AWS Cloud.
automate the patch management process of the operating system in which their database will run
set up scheduled backups to comply with the disaster recovery plan of the company.

# Question
LEAST amount of effort

# Options
1. Migrate the on-premises database to Aurora. Enable automated backups for your Aurora RAC cluster. With Aurora, patching is automatically handled during the system maintenance window.
2. Migrate the database that is hosted on-premises to RDS which provides a multi-AZ failover feature for your Oracle RAC cluster. The RPO and RTO will be reduced in the event of system failure since RDS offers features such as patch management and maintenance of the underlying host.
3. Migrate the Oracle RAC database to a large EBS-backed EC2 instance then install the SSM agent. Use the Systems Manager Patch Manager to automate the patch management process. Set up the Data Lifecycle Manager service to automate the creation of EBS snapshots from the EBS volumes of the EC2 instance.

# Explanation
Oracle RAC is supported via the deployment using EC2 only since RDS and Aurora do not support it. RDS does not support certain features in Oracle such as Multitenant Database, Real Application Clusters (RAC), Unified Auditing, Database Vault and many more.

1. just like RDS, the Aurora doesn't support Oracle RAC as well.
2. RDS doesn't support Oracle RAC.
