# Scenario
Lambda functions are used for the public APIs. For its database-tier, a DynamoDB table stores all of the data with an OpenSearch Service domain, which supports the search feature and stores the indexes.

In the event of a failed deployment, there should be no downtime and a system should be in place to prevent subsequent deployments.

# Question
MOST efficient way?

# Options
1. Deploy the DynamoDB tables, Lambda functions, and OpenSearch Service domain using CloudFormation. Deploy changes with a CodeDeploy blue/green deployment. Host the web application in Elastic Beanstalk and set the deployment policy to All at Once.
2. Deploy the DynamoDB tables, Lambda functions, and OpenSearch Service domain using CloudFormation. Deploy changes with a CodeDeploy blue/green deployment. Host the web application in Elastic Beanstalk and set the deployment policy to Immutable.
3. Deploy the DynamoDB tables, Lambda functions, and OpenSearch Service domain using CloudFormation. Deploy changes with a CodeDeploy blue/green deployment. Host the web application in S3 and enable cross-region replication.

# Explanation
Immutable deployments perform an immutable update to launch a full set of new instances running the new version of the application in a separate ASG, alongside the instances running the old version. Immutable deployments can prevent issues caused by partially completed rolling deployments. If the new instances don't pass health checks, Elastic Beanstalk terminates them, leaving the original instances untouched.
