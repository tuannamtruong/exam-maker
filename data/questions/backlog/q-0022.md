# Scenario
A company wants to scale the throughput of its AWS Site-to-Site VPN connections.

# Question
Which solution should the architect carry out?

# Options
1. Re-route some of the VPN connections to a secondary customer gateway device on the remote network's end.
2. Associate the VPCs to an ECMP-enabled transit gateway and attach additional VPN tunnels.
3. Add more virtual private gateways to a VPC and enable ECMP to get higher VPN bandwidth.
4. Modify the VPN configuration by increasing the number of tunnels to scale the throughput.

# Explanation
With AWS Transit Gateway, you can simplify the connectivity between multiple VPCs and also connect to any VPC attached to AWS Transit Gateway with a single VPN connection.

AWS Transit Gateway also enables you to scale the IPsec VPN throughput with ECMP routing support over multiple VPN tunnels. A single VPN tunnel still has a maximum throughput of 1.25 Gbps. If you establish multiple VPN tunnels to an ECMP-enabled transit gateway, it can scale beyond the default limit of 1.25 Gbps.

1. This would only increase connection redundancy and won’t increase throughput. For example, connections can fail over to the secondary customer gateway device in case the primary customer gateway device becomes unavailable.
3. a VPC can only have a single virtual private gateway attached to it one at a time. Also, there is no option to enable ECMR in a virtual private gateway.
4. The maximum tunnel for a VPN connection is two. You cannot increase this beyond its limit.
