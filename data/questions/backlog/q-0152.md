# Scenario
If the latency of the service increases more than the defined threshold then the deployment should be halted until the service has been fully recovered.

# Question
FASTEST detection time for deployment issues?

# Options
1. Define the thresholds to roll back the deployments based on the latency using the MinimumHealthyHosts deployment configuration in AWS CodeDeploy. Rollback the deployment if the threshold was breached.
2. Calculate the average latency using Amazon CloudWatch metrics that monitors the Application Load Balancer. Associate a CloudWatch alarm with the CodeDeploy deployment group. When latency increases beyond the defined threshold, it will automatically trigger an alarm that automatically stops the on-going deployment.
3. Collect the ELB access logs and use a Lambda function to calculate and detect the average latency of the service. When latency increases beyond the defined threshold, trigger the alarm and stop the current deployment.
4. Enable Detailed Monitoring in CloudWatch to monitor and detect the latency in the Application Load Balancer. When latency increases beyond the defined threshold, trigger a CloudWatch alarm and stop the current deployment.

# Explanation
You can associate up to ten CloudWatch alarms with a CodeDeploy deployment group. If any of the specified alarms are activated, the deployment stops, and the status is updated to Stopped. You must grant CloudWatch permissions to your CodeDeploy service role to use this option.

1. because the MinimumHealthyHosts is just a property of the DeploymentConfig resource that defines how many instances must remain healthy during an AWS CodeDeploy deployment. It doesn’t calculate the latency of the service.
3. Although ELB access logs contain latency information, you still need to parse the data using Lambda. The calculation process entails a significant amount of time. A faster solution would be to use Amazon CloudWatch metrics.
4. because you cannot enable detailed monitoring in your Application Load Balancer. The detailed monitoring feature in CloudWatch is primarily used to collect data from your EC2 and other resources in 1-minute frequency for an additional cost. This level of frequency is already available for your load balancers. If there are requests flowing through the load balancer, Elastic Load Balancing measures and sends its metrics in 60-second intervals.
