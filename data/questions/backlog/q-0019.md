# Scenario
A corporation has several Windows file servers across departments in its on-premises data center. To improve data management and scalability, it must migrate and integrate its files into an FSx for Windows File Server file system while keeping the current file permissions intact.

# Question
Which solutions will fulfill the company's requirements? (Select TWO.)

# Options
1. Utilize the AWS CLI to copy the file shares from each on-premises file server to an S3 bucket. Then, schedule AWS DataSync tasks to move the data from S3 to the FSx for Windows File Server file system.
2. Use AWS Storage Gateway to create a file gateway, then mount the file gateway on the on-premises file servers. Migrate the data from the file servers to the file gateway, and then use AWS DataSync to move the data from the file gateway to the FSx for Windows File Server file system.
3. Acquire an AWS Snowcone device, then connect with the on-premises network. Use AWS OpsHub to launch the AWS DataSync agent AMI and activate the agent via the AWS Management Console. Schedule DataSync tasks to transfer the data to the FSx for Windows File Server file system.
4. Order an AWS Snowball Edge Storage Optimized device, link it to the on-premises network, and transfer data using the AWS CLI. Return the device to AWS for data import into S3. Configure AWS DataSync tasks to migrate the data from S3 to the FSx for Windows File Server file system.
5. Set up AWS DataSync agents on the corporation's on-premises file servers and schedule DataSync tasks for transferring data to the FSx for Windows File Server file system.

# Explanation
Migrating and integrating files into an FSx for Windows File Server file system while keeping the current file permissions intact can be easily achieved using a combination of AWS services. First, the AWS Snowcone device can collect the files from the current storage system, even in remote locations where traditional computing resources are unavailable.

Next, AWS DataSync agents can be installed on the source and target storage systems. These agents facilitate data transfer between them, ensuring a highly reliable and secure transfer with support for various data transfer protocols, including NFS, SMB, and S3. DataSync tasks can be scheduled to run automatically or initiated manually, providing flexibility and control over the transfer process.

1. While this approach could work, it introduces unnecessary complexity by copying to S3 before transferring to FSx for Windows File Server. Thus, it doesn’t directly ensure that the file permissions are maintained throughout the migration process. An AWS DataSync agent can typically be used here instead of manually using the AWS CLI to copy the data on-premises to AWS.
2. Storage Gateway primarily facilitates hybrid cloud storage use cases rather than direct migrations while maintaining existing file permissions.
4. This introduces additional steps and unnecessary complexity when it comes to syncing the on-premises file server to the FSx storage service in AWS. There’s no need to use a Snowball device since AWS DataSync can directly transfer data from on-premises to FSx for Windows File Server online.
