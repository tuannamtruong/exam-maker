# Scenario
A company needs to capture detailed information of all HTTP requests that went through its public-facing ALB every five minutes. The client's IP address and network latencies must also be tracked, while the load balancer's availability is monitored separately through the ELB health check. The captured data should be used for analyzing traffic patterns and for troubleshooting Docker applications orchestrated by the ECS Anywhere service.

# Question
Which option has the LEAST amount of overhead?

# Options
1. Enable AWS CloudTrail for their ALB. Use the CloudTrail Lake to analyze and troubleshoot the application traffic.
2. Enable access logs on the ALB. Integrate the ECS cluster with CloudWatch Application Insights to analyze traffic patterns and simplify troubleshooting.
3. Install and run the AWS X-Ray daemon on the ECS cluster. Use the CloudWatch ServiceLens to analyze the traffic that goes through the application.

# Explanation
1. AWS CloudTrail is primarily used to monitor and record the account activity across your AWS resources and not your web applications. You cannot use CloudTrail to capture the detailed information of all HTTP requests that go through your public-facing ALB. CloudTrail can only track the resource changes made to your ALB, but not the actual IP traffic that goes through it. For this use case, you have to enable the access logs feature instead. In addition, the AWS CloudTrail Lake feature is more suitable for running SQL-based queries on your API events and not for analyzing application traffic.
3. Although this solution is possible, this won’t track the client’s IP address since the access log feature in the ALB is not enabled. Take note that the scenario explicitly mentioned that the client’s IP address and network latencies must also be tracked.
