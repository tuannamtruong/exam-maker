# Scenario
CodeCommit + CodePipeline. The team has decided to use a remote main branch as the trigger for the pipeline to integrate code changes.code changes to the CodeCommit repository, but the pipeline had no reaction, even after 10 minutes.

# Question
troubleshoot this issue?

# Options
1. Check that an EventBridge rule has been created for the main branch to trigger the pipeline.
2. Check that the CodePipeline service role has permission to access the CodeCommit repository.
3. Check that the developer's IAM role has permission to push to the CodeCommit repository.
4. Check to see if the pipeline failed to start because of CodeCommit errors in CloudWatch Logs.

# Explanation
CodePipeline detects CodeCommit pushes via an EventBridge rule.

2. If the pipeline's service role lacked CodeCommit access, the pipeline would still start (triggered by the event) and then fail at the Source stage. The symptom is no reaction, not a failure.
3. The developer clearly did push successfully ("code changes to the CodeCommit repository"), so their push permission is fine.
4. "Pipeline failed to start because of CodeCommit errors" isn't a real failure mode here; if nothing triggers the pipeline, there are no start-failure logs to find. The gap is the missing trigger, not a logged error.
