# Scenario
DynamoDB table must be available in all three regions to deliver low-latency data access.

When the table is updated in one Region, the change must seamlessly propagate to the other regions.

# Question
LEAST operational overhead?

# Options
1. Create DynamoDB global tables, then configure a primary table in one region and a read replica in the other regions.
2. Provision a multi-Region, multi-active DynamoDB global table that includes the three Regions.

# Explanation
DynamoDB global tables provide a fully managed solution for deploying a multi-Region, multi-active database without having to build and maintain your own replication solution.

1. global tables do not have read replicas.
