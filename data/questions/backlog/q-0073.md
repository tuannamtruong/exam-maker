# Scenario
a solution that would automatically terminate any EC2 instance in production that was manually logged into via SSH. All of the EC2 instances that are being used by the application already have a CloudWatch Logs agent installed.

# Question
Which of the following is the MOST automated solution that the DevOps engineer should implement?

# Options
1. Set up and integrate a CloudWatch Logs subscription with Step Functions to add a special FOR_DELETION tag to the specific EC2 instance that had an SSH login event. Create an EventBridge rule to trigger a second Lambda function everyday at 12 PM that will terminate all of the EC2 instances with this tag.
2. Set up a CloudWatch Logs subscription with a Lambda function which is configured to add a FOR_DELETION tag to the EC2 instance that produced the SSH login event. Run another Lambda function every day using the EventBridge rule to terminate all EC2 instances with the custom tag for deletion.
3. Set up a CloudWatch Alarm that will be triggered when there is an SSH login event and configure it to send a notification to a Simple Queue Service (SQS) queue. Launch a group of EC2 worker instances to consume the messages from the SQS queue and terminate the detected EC2 instances.

# Explanation
1. a CloudWatch Logs subscription cannot be directly integrated with a Step Functions application.

3. using SQS as well as worker instances is unnecessary since you can simply use Lambda functions for processing. In addition, CloudWatch Alarms can only send notifications to SNS and not SQS.
