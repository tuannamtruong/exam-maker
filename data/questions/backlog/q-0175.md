# Scenario
web logs in Kinesis Data Streams. Processes the logs using a consumer application running on EC2.
During traffic spikes:
The consumer cannot keep up.
Records expire before they are processed.

# Question
least operational effort?

# Options
1. Modify the consumer to store logs in S3. Use EMR to process the data in S3.
2. Horizontally scale the EC2 consumer based on the CloudWatch GetRecords.IteratorAgeMilliseconds metric. Increase the Kinesis stream retention period.
3. Convert the consumer to a Lambda function. Configure the Kinesis data stream as the Lambda event source.
4. Increase the number of Kinesis shards.

# Explanation
Converting the consumer to a Lambda function and configuring the Kinesis data stream as the Lambda event source lets Lambda automatically scale to keep up with traffic spikes — there are no EC2 instances to manage or scale, so this is the least operational effort.

1. Irrelevant.
2. Solves the problem, but more efficiently at the cost of more operational overhead.
4. The bottleneck is in the EC2 consumer, not the shard count, so adding shards does not help.
