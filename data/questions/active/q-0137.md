# Scenario
CloudFormation to deploy its infrastructure.
restrict deployment to two particular regions and wants to implement a strict tagging requirement.
various versions of the same application and want to guarantee that resources are deployed in compliance with the business policy while still enabling developers to deploy different versions of the application.

# Options
1.	Detect and remediate unapproved CloudFormation Stacksets by creating AWS Trusted Advisor checks. 
2.	Utilize AWS Service Catalog and create products with approved CloudFormation templates. 
3.	Utilize approved CloudFormation templates and launch CloudFormation StackSets. 
4.	Detect and remediate unapproved CloudFormation Stacksets by creating a CloudFormation drift detection operation. 

# Explanation

AWS Service Catalog - Template constraints can be applied when limiting end-users’ options during a product launch.
1. because Trusted Advisor does not support checks for unauthorized StackSets or enforce CloudFormation template compliance.
3. because StackSets manage deployments across accounts and regions but do not enforce tagging or region restrictions. They do not typically provide governance to prevent non-compliant implementations.
4. because drift detection only identifies changes after deployment, but cannot prevent non-compliant resource creation or enforce policies before deployment.
