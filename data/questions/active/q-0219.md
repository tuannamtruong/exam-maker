# Scenario
A gaming company runs the backend for a multiplayer game on EC2 instances managed through Elastic Container Service (ECS). The company uses CodeDeploy to automate the deployment of new game updates to its servers. However, deployment failures have recently been encountered more frequently, leading to downtime for players. A solution is required to notify developers and other stakeholders via email so remediations can be administered promptly.

# Question
Which of the options would meet the requirements with the LEAST overhead?

# Options
1. Set up an SNS topic for failed deployments. Configure a CloudWatch alarm to send failed deployment messages to the SNS topic. Have stakeholders subscribe to the SNS topic using each of their personnel emails or an appropriate distribution list.
2. Set up an SNS topic for failed deployments. Configure a CodeDeploy trigger and set the SNS topic as destination. Have stakeholders subscribe to the SNS topic using each of their personnel emails or an appropriate distribution list.
3. Set up an SES email for failed deployments. Configure a CloudWatch alarm to send failed deployment notifications to the SES email.
4. Enable CloudWatch to collect CodeDeploy logs. Set up SNS topic for failed deployments. Create a Lambda function to send messages to the SNS topic. Set up an EventBridge rule to intercept failed deployment logs with the Lambda function as target.

# Explanation
CodeDeploy has built-in triggers for deployment events, including deployment failure, that publish straight to an SNS topic.

1. CloudWatch alarms fire on metrics, and CodeDeploy does not emit a native "failed deployment" metric to alarm on. You would have to manufacture one (a metric filter over logs), which is more work than a native trigger.
3. Although it could work, setting up CloudWatch to trigger SES involves creating a mechanism to format and send emails, which may not be as straightforward as using Amazon SNS.
4. Roundabout way to achieve email notifications for failed deployments.
