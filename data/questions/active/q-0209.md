# Scenario
Developers use:
- CodeCommit
- CodePipeline
- CodeBuild
- CodeDeploy

Pull requests are being merged before long-running tests finish, causing rollbacks.

The company wants tests to run automatically for every pull request, and reviewers should see the test results during the PR review.

# Question
What should the DevOps engineer do to meet this requirement?

# Options
1. Create an EventBridge rule that reacts to the pullRequestCreated event. Create a Lambda function that invokes a CodePipeline pipeline with a CodeBuild action that runs the tests for the application. Program the Lambda function to post the CodeBuild test results as a comment on the pull request when the test results are complete.
2. Create an EventBridge rule that reacts to pullRequestCreated and pullRequestSourceBranchUpdated events. Create a Lambda function that invokes a CodePipeline pipeline with a CodeBuild action that runs the tests for the application. Program the Lambda function to post the CodeBuild badge as a comment on the pull request so that developers will see the badge in their code review.
3. Create an EventBridge rule that reacts to the pullRequestStatusChanged event. Create a Lambda function that invokes a CodePipeline pipeline with a CodeBuild action that runs the tests for the application. Program the Lambda function to post the CodeBuild test results as a comment on the pull request when the test results are complete.

# Explanation
Two important requirements:

1. Automatically test every pull request.
2. Re-test whenever new commits are pushed to the pull request.

Badge is acceptable, it satisfies the visibility requirement.

1. Developer creates PR -> (Tests run: PASS) -> Reviewer requests changes -> Developer pushes new commit -> No new tests run -> Reviewer merges broken code
3. pullRequestStatusChanged: statues after the review lifecycle has progressed.
