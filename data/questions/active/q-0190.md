# Scenario
A company has 500 AWS accounts in an Organization.

Every account needs a Lambda function that:

checks for unattached EBS volumes
finds volumes that have been unattached for 7+ days
tags those volumes for investigation
runs every 30 minutes

The solution must be highly automated and require the least operational effort.

# Options
1. Configure a delegated administrator account for the organization. Create a CloudFormation template that contains the Lambda function. Use CloudFormation StackSets to deploy the CloudFormation template from the delegated administrator account to all the member accounts in the organization. Create an EventBridge event bus in the delegated administrator account to invoke the Lambda function in each member account every 30 minutes.
2. Create a cross-account IAM role in the organization's member accounts. Attach the AWSLambda_FullAccess policy and the AWSCloudFormationFullAccess policy to the role. Create a CloudFormation template that contains the Lambda function and an EventBridge scheduled rule to invoke the Lambda function every 30 minutes. Create a custom script in the organization's management account that assumes the role and deploys the CloudFormation template to the member accounts.
3. Configure a delegated administrator account for the organization. Create a CloudFormation template that contains the Lambda function and an EventBridge scheduled rule to invoke the Lambda function every 30 minutes. Use CloudFormation StackSets to deploy the CloudFormation template from the delegated administrator account to all the member accounts in the organization.

# Explanation
CloudFormation StackSets are designed exactly for this use case. The StackSet deploys the same stack into every account. Each deployed stack contains: Lambda, IAM role, EventBridge scheduled rule. If StackSets can deploy infrastructure across Organizations, don't write custom deployment scripts.

1. After deployment it creates an EventBridge event bus in the delegated admin account to invoke every Lambda. This is unnecessary. This means the trigger comes from the delegated admin, instead of inside the local account.
2. This introduces unnecessary custom automation: IAM roles, deployment scripts, assume roles, deploy manually. StackSets solves this.
