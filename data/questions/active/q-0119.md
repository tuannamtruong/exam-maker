# Scenario
pre-approved AMIs only.
Development team has an automated CI/CD process that launches several EC2 instances with new and untested AMIs for testing.
development process must not be affected by the new solution

# Options
1. Use Config with a Lambda function that periodically evaluates whether there are EC2 instances launched based on non-approved AMIs. Set up a remediation action using Systems Manager Automation that will automatically terminate the EC2 instance. Publish a message to an SNS topic to inform the IT Security and Development teams about the occurrence.
2. Integrate Lambda and CloudWatch Events to schedule a daily process that will search through the list of running EC2 instances within your VPC. Configure the function to determine if any of these are based on unauthorized AMIs. Publish a new message to an SNS topic to inform the Security and Development teams that the issue occurred and then automatically terminate the EC2 instance.
3. Set up IAM policies to restrict the ability of users to launch EC2 instances based on a specific set of pre-approved AMIs which were tagged by the IT Security team.

# Explanation
3. setting up an IAM Policy will totally restrict the development team from launching EC2 instances with unapproved AMIs which could impact their CI/CD process. The scenario clearly says that the solution should not have any interruption in the company's development process.
