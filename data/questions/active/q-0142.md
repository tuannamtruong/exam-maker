# Scenario
The backend APIs will be launched to multiple AWS regions.
system architecture to ensure that the transactions made in one region are automatically replicated to other regions.
millions of users.

# Question
MOST scalable, cost-effective and highly available architecture?

# Options
1.	Set up an Aurora Multi-Master database on all of the required AWS regions. Store the individual transactions to the Amazon Aurora instance in the local region and replicate the transactions across regions using Aurora replication. Any changes made in one of the tables will be automatically replicated across all other tables. 
2.	Store the individual transactions in each local region in an Amazon DynamoDB table. Use an AWS Lambda function to read recent writes from the primary DynamoDB table and replay the data to tables in all other regions. 
3.	Set up an Amazon DynamoDB Global table in your preferred AWS region and enable the DynamoDB Streams option. Set up replica tables in the other AWS regions where you want to replicate your data. In each local region, store the individual transactions in a DynamoDB replica table in the same region. 
4.	Create an Amazon DynamoDB Global Table across the required AWS Regions. Store the individual transactions in the local region’s replica table. Any changes made in one of the replica tables are automatically replicated across all other replica tables worldwide.

# Explanation
1. Aurora Multi-Master is not global
Aurora Multi-Master works within a single region only
It does not support cross-region active-active writes
2. because this requires building and maintaining custom replication logic, which introduces additional operational complexity, higher latency, and greater potential for data inconsistency. DynamoDB Global Tables already provide automatic, fully managed, multi-Region replication without requiring custom Lambda-based replication pipelines, making this option less scalable and more costly.
3. because DynamoDB Global Tables already enable and use DynamoDB Streams automatically to handle change data capture and cross-Region replication. Customers do not need to manually enable Streams or configure replication themselves. This option incorrectly suggests that manual setup is required, while in reality AWS manages the Streams integration and replication process in the background.
