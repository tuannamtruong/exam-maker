# Scenario
A centralized DevOps account contains a CodeBuild project that deploys applications into EKS clusters located in separate application accounts.  The deployment fails with:  Unauthorized  when CodeBuild attempts to connect to the EKS cluster in another AWS account.

# Options
1.	Configure the application account’s deployment IAM role to have a trust relationship with the centralized DevOps account. Configure the trust relationship to allow the sts:AssumeRole action. Configure the application account’s deployment IAM role to have the required access to the EKS cluster. Configure the EKS cluster aws-auth ConfigMap to map the role to the appropriate system permissions. 
2.	Configure the centralized DevOps account’s deployment IAM role to have a trust relationship with the application account. Configure the trust relationship to allow the sts:AssumeRole action. Configure the centralized DevOps account’s deployment IAM role to allow the required access to CodeBuild. 
3.	Configure the centralized DevOps account’s deployment IAM role to have a trust relationship with the application account. Configure the trust relationship to allow the sts:AssumeRoleWithSAML action. Configure the centralized DevOps account’s deployment IAM role to allow the required access to CodeBuild. 
4.	Configure the application account’s deployment IAM role to have a trust relationship with the AWS Control Tower management account. Configure the trust relationship to allow the sts:AssumeRole action. Configure the application account’s deployment IAM role to have the required access to the EKS cluster. Configure the EKS cluster aws-auth ConfigMap to map the role to the appropriate system permissions.


# Explanation
This question combines two separate authorization layers that EKS requires. 
Cross-account IAM access + EKS authorization.

To obtain credentials in another account, it must call: sts: AssumeRole
The assumed IAM role must also appear in the EKS cluster's: aws-auth ConfigMap

2. 3. The trust relationship is backwards.
4. The AWS Control Tower management account is irrelevant. CodeBuild is running in the centralized DevOps account, not in the management account.
