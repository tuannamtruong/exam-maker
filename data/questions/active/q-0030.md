# Scenario
A company has a mission-critical, public-facing containerized application running on an EKS cluster with microservices architecture. There is a requirement to implement a fully managed centralized application logging solution that automatically collects metrics and application logs. The company also requires a dashboard to easily monitor the application metrics.

# Question
Which solution meets the requirements with the LEAST amount of operational overhead?

# Options
1. Install and set up the CloudWatch agent on the EKS cluster to collect the metrics. Use the CloudWatch dashboard to view the application logs.
2. Set up and configure Managed Service for Prometheus metrics collection for the EKS cluster by installing the Prometheus agent on all EKS pods. Launch a dashboard in Managed Grafana to visualize metrics and logs in EKS.
3. Use CloudWatch Container Insights with the EKS cluster. Use the CloudWatch dashboard to view the application logs and metrics.

# Explanation
CloudWatch Container Insights automatically collects, aggregates, and summarizes metrics and logs from EKS/ECS/Kubernetes — minimal config and built-in dashboards. CloudWatch agent on EKS requires manual log path configuration on every node. Managed Prometheus + Grafana adds dashboard operational overhead.
