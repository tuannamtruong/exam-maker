# Scenario
A company is enforcing a compliance policy that restricts the operation of its AWS resources to specific regions within the Asia Pacific. One of its DevOps engineers was instructed to come up with a solution that sends an alert to the admin if an activity occurs outside the Asia Pacific. Also, the solution must be applied automatically to new Regions that will be launched in the future.

# Question
Which combination of actions should the engineer take to meet these requirements? (Select TWO.)

# Options
1. Create a service control policy that restricts operation access to regions within the Asia Pacific using the aws:RequestedRegion condition key. Attach the SCP to all IAM identities.
2. Write a Lambda function that scans AWS activities and sends an alert if an activity is detected in regions outside of Asia Pacific. Deploy the function in all regions. Create a scheduled rule in EventBridge to trigger the Lambda function every 30 minutes.
3. Attach a service control policy to the organization root that allows operations from approved regions and denies access to non-global services on regions outside the Asia Pacific.
4. Use Inspector to run a weekly assessment of activities done in non-Asia Pacific regions. Send an alert if an activity is detected.
5. Enable CloudTrail to deliver logs from all regions to CloudWatch Logs. Then, create a metric filter that sends an alert whenever an activity in non-Asia Pacific regions occurs.

# Explanation
1. you cannot attach a service control policy (SCP) to IAM identities. SCPs can only be attached to the root, OU, or account that you want to attach the policy to.

2. You don't have to implement this and reinvent the wheel. CloudTrail is specifically designed for this type of task. Additionally, this method won't automatically extend the monitoring to new regions.

4. Inspector is just an automated security assessment service that can help you identify vulnerabilities on your EC2 instances.
