# Scenario
A company currently has a mostly manual deployment process:

- Application runs on EC2.
- Infrastructure is managed by CloudFormation.
- Source code and CloudFormation templates are now in CodeCommit.
- CodeBuild already builds and tests the application.

They want to automate everything.

They must keep a final manual approval before any infrastructure or application changes occur.

# Question
TWO

# Options
1. Create an application group and a deployment group in CodeDeploy. Install the CodeDeploy agent on the EC2 instances.
2. Create an application revision and a deployment group in CodeDeploy. Create an environment in CodeDeploy. Register the EC2 instances to the CodeDeploy environment.
3. Use CodePipeline to invoke the CodeBuild job, run the CloudFormation update, and pause for a manual approval step. After approval, start the CodeDeploy deployment.
4. Use CodePipeline to invoke the CodeBuild job, create CloudFormation change sets for each of the application stacks, and pause for a manual approval step. After approval, run the CloudFormation change sets and start the CodeDeploy deployment.
5. Use CodePipeline to invoke the CodeBuild job, create CloudFormation change sets for each of the application stacks, and pause for a manual approval step. After approval, start the CodeDeploy deployment.

# Explanation
Req 1 - Automate deployment to EC2 -> CodeDeploy.
This needs:
a CodeDeploy Application
a Deployment Group
the CodeDeploy Agent installed on every EC2 instance
-> 1

Req 2 - Infrastructure deployment -> 4

2. There is no CodeDeploy Environment.
Register EC2 instances to the environment. Also not CodeDeploy behaviour.

Deployment Groups identify EC2 instances by:
 EC2 tags
 Auto Scaling Groups
