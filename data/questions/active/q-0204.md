# Scenario
EC2 instances in an ASG behind an ALB with Multi-AZ RDS. Deployments use CloudFormation with the AutoScalingRollingUpdate policy. Many stack updates are failing, causing outages. The goal is to determine what is preventing the ASG from updating correctly. (Select THREE.)

# Options
1. Switch from AutoScalingRollingUpdate to AutoScalingReplacingUpdate policy by modifying the UpdatePolicy of the AWS::AutoScaling::AutoscalingGroup resource in the CloudFormation template. Set the WillReplace property to true.
2. In your AutoScalingRollingUpdate policy, set the value of the MinSuccessfulInstancesPercent property to prevent CloudFormation from rolling back the entire stack if only a single instance fails to launch.
3. During a rolling update, suspend the following Auto Scaling processes: HealthCheck, ReplaceUnhealthy, AZRebalance, AlarmNotification, and ScheduledActions.
4. In your AutoScalingRollingUpdate policy, set the WaitOnResourceSignals property to false.
5. Suspend the following Auto Scaling processes that are related with your ELB: Launch, Terminate, and AddToLoadBalancer.
6. Set the WaitOnResourceSignals property to true in your AutoScalingRollingUpdate policy.

# Explanation
To find out what's preventing your ASG from updating correctly during a stack update:

- Configure WaitOnResourceSignals and PauseTime to avoid problems with success signals. -> 4
- Configure MinSuccessfulInstancesPercent to avoid stack rollback. -> 2
- Configure SuspendProcesses to avoid unexpected changes to the ASG. -> 3

1. Although the AutoScalingReplacingUpdate policy provides an immediate rollback of the stack without any possibility of failure, this solution is not warranted since the scenario asks for the options that will help troubleshoot the issue.
5. These processes are required by the ELB to make rolling updates.
6. The WaitOnResourceSignals property should be set to false instead of true, to determine what prevents the ASG from being updated correctly during a stack update.
