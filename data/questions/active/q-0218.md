# Scenario
A company uses a kernel plugin via eBPF for security and observability purposes on EC2. The DevOps team manages thousands of instances, each tagged with either prod, stg, or dev. Latest versions of the plugin are always applied to stg-tagged instances, dev-tagged instances, on the other hand, can use any older version up to the version with the latest critical patch, and prod-tagged instances with one version older from latest, for stability. A solution is required to retrieve an updated list of all nodes with the versions of the plugin they are installed with, along with other system information.

# Question
Which option will fit the requirements with the LEAST operational overhead?

# Options
1. Create a Systems Manager custom inventory for the plugin. Run a script on each node to determine its instance tag and version. Use Systems Manager Session Manager to connect to nodes and execute the script securely. Export results to an S3 bucket. Use Athena to query inventory findings.
2. Create a Systems Manager custom inventory for the plugin. Populate custom inventory metadata for the plugin version using a script with the Systems Manager Run command. Set target nodes with tag value of prod, stg, or dev. Use resource data sync to trail changes to inventory metadata to S3. Use Athena to query inventory findings.
3. Assign a resource tag key for the plugin. Use Systems Manager Run Command to determine the plugin version, populate the resource tag value accordingly, and export findings to S3. Use Athena to query inventory findings.
4. Turn on SSM:ManagedInstanceInventory in Config. Create a Systems Manager custom inventory for the plugin. Use Athena to query inventory findings.

# Explanation
Systems Manager Run Command enables commands to be executed at scale using `targets`. In this scenario, all managed instances, including on-premises servers, are configured targets for a script that populates custom inventory metadata indicating the version of the plugin. With resource data sync enabled, any changes in inventory metadata are synced to the configured S3 bucket.

1. Using Session Manager to run the script may prevent the provisioning of infrastructure to support safely connecting to instances/servers. However, having to run a script manually on a regular basis is a significant operational overhead.
3. Although it is possible to utilize a custom resource tag for this purpose, this solution requires additional overhead to retrieve the same node metadata that is available to the Systems Manager Inventory by default.
4. Aside from not specifying an action to populate the custom inventory, using AWS Config in this scenario is an overkill, if not a convoluted way of retrieving a list of inventory metadata.
