# Scenario
Validation scripts need to be run for new deployments to determine if the application is working as expected before allowing production traffic to flow to the new app version. Automatic rollback should also be configured if the validation is not successful.

# Question
Which?

# Options
1. Create validation scripts in Lambda and define on the AfterInstall lifecycle hook of the AppSpec.yaml file. The functions can validate the deployment after installing the new version and rollback if the tests fail.
2. Create validation scripts in Lambda and define them on the AfterAllowTestTraffic lifecycle hook of the AppSpec.yaml file. The functions can validate the deployment using the test traffic and rollback if the tests fail.
3. Create validation scripts in Lambda and define them on the BeforeAllowTraffic lifecycle hook of the AppSpec.yaml file. The functions can validate the deployment before allowing production traffic and rollback if the tests fail.

# Explanation
On the AfterAllowTestTraffic hook, you can specify Lambda functions that can validate the deployment using the test traffic.

1. in the AfterInstall lifecycle hook, the new task version is not yet attached on the test listener and ALB, therefore, no traffic is flowing yet on this cluster.
3. in the BeforeAllowTraffic lifecycle hook, validation has already succeeded, which only defeats its purpose. You have to use this hook to perform additional actions before allowing production traffic to flow to the new task version.
