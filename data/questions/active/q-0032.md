# Scenario
A multinational corporation is migrating its legacy applications from an on-premises Microsoft Active Directory to AWS. These applications are spread across multiple AWS accounts managed collectively by AWS Organizations. The corporation needs an SSO solution that allows the security team to use their current Active Directory credentials for authentication across all AWS accounts, and to maintain centralized user and group management in their existing on-premises AD.

# Question
Which approach should the corporation take?

# Options
1. Implement AWS Directory Service's Managed Microsoft AD (Enterprise Edition). Set up the Active Directory as the principal identity provider for AWS IAM Identity Center.
2. Set up an external IdP on an EC2 instance. Integrate this IdP with AWS IAM Identity Center as the identity source.
3. Utilize AWS Directory Service to establish a two-way trust relationship with the corporation's self-managed Active Directory for mutual authentication and access control.
4. Activate AWS IAM Identity Center and establish a two-way forest trust relationship. Link the corporation's AD with the IAM Identity Center via AWS Managed Microsoft AD.

# Explanation
1. This option is focused on implementing AWS Managed Microsoft AD and setting it up as the principal identity provider for AWS IAM Identity Center. it does not explicitly mention establishing a trust relationship with the on-premises AD. This lack of a direct trust relationship may hinder seamless integration and management of user identities and access controls between the on-premises and cloud environments, limiting the ability to maintain administration within the existing on-premises AD.
2. Setting up an external identity provider on an EC2 instance can only introduce complexity and security concerns. Developing, securing, and maintaining the IdP software running on EC2 requires significant effort, detracting from the simplicity and security benefits of using AWS-managed services. This approach could also lead to latency and reliability issues and diverges from leveraging the corporation’s existing Microsoft Active Directory, potentially complicating user and group management within its on-premises infrastructure.
3. While this option promotes mutual authentication and access control, it primarily facilitates access between on-premises and AWS resources rather than providing a comprehensive solution for managing access across multiple AWS accounts. It lacks integration with the AWS IAM Identity Center, which is critical for centralized access management to AWS accounts and applications, making it less suitable for creating a unified authentication framework across the corporation’s entire AWS environment.
