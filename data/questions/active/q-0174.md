# Scenario
When GuardDuty detects a suspicious IP address, the company wants to automatically block all traffic from that source across the VPC.

# Question
solution automatically blocks malicious traffic throughout the VPC when GuardDuty generates a finding?

# Options
1. Create a GuardDuty threat list. Configure GuardDuty to reference the list. Create a Lambda function that updates the threat list. Invoke the Lambda function from new Security Hub findings.
2. Configure a WAF web ACL with a custom rule group. Create a Lambda function that creates a block rule in the rule group. Invoke the Lambda function from new Security Hub findings.
3. Configure Network Firewall. Create a Lambda function that creates a Drop rule in the firewall policy. Invoke the Lambda function from new Security Hub findings.
4. Create a Lambda function that creates a GuardDuty suppression rule. Invoke the Lambda function from new Security Hub findings.

# Explanation
The solution must operate at the network layer for all workloads in the VPC. Network Firewall does this: a Lambda function creates a Drop rule in the firewall policy in response to the finding, blocking traffic from the malicious source across the VPC.

1. A threat list is not a firewall. It simply provides GuardDuty with additional indicators of compromise to improve threat detection. It does not block traffic.
2. WAF only protects supported HTTP(S) resources.
4. A suppression rule tells GuardDuty to ignore certain findings.
