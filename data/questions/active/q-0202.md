# Scenario
A global payment processing application uses: EC2, DynamoDB, S3, CloudFront

Requirements:
Meet PCI DSS compliance by protecting credit card numbers.
Increase CloudFront cache hit ratio to improve performance.

# Options
1. Use a custom SSL in the CloudFront distribution. Configure your origin to add User-Agent and Host headers to your objects to increase your cache hit ratio.
2. Set up an origin access identity (OAI) and add it to the CloudFront distribution. Configure your origin to add User-Agent and Host headers to your objects to increase your cache hit ratio.
3. Secure end-to-end connections to the origin servers in your CloudFront distribution by using HTTPS and field-level encryption. Set up your origin to add a Cache-Control max-age directive to your objects. Apply the longest practical value for max-age to increase your cache hit ratio.

# Explanation
HTTPS protects the connection by encrypting and decrypting the traffic. Field-level encryption additionally encrypts selected fields inside the request, so they stay encrypted beyond the TLS session. Setting a Cache-Control max-age directive with the longest practical value increases the CloudFront cache hit ratio, which means more cache hits and better performance.

1. Although it provides secure end-to-end connections to origin servers, it is better to add field-level encryption to protect the credit card information.
2. OAI is mainly used to restrict access to objects in S3 bucket, but does not provide encryption to specific fields.
