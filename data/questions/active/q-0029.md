# Scenario
A large electronics company uses S3 to store important documents. For reporting, they want to track and log every request access including the requester, bucket name, request time, request action, referrer, turnaround time, and error code information. The solution should also provide more visibility into object-level operations.

# Question
Which is the best solution?

# Options
1. Enable server access logging for all required S3 buckets.
2. Enable AWS CloudTrail to audit all S3 bucket access.
3. Enable S3 Event Notifications for PUT and POST.

# Explanation
AWS CloudTrail logs provide a record of actions taken by a user, role, or an AWS service in S3, while S3 server access logs provide detailed records for the requests that are made to an S3 bucket.

For this scenario, you can use CloudTrail and the Server Access Logging feature of S3. However, it is mentioned in the scenario that they need detailed information about every access request sent to the S3 bucket including the referrer and turn-around time information. These two records are not available in CloudTrail.

CloudTrail captures a subset of API calls for S3 as events, including calls from the S3 console and code calls to the S3 APIs.

2. enabling AWS CloudTrail alone won’t give detailed logging information for object-level access.
3. we are looking for a logging solution and not an event notification.
