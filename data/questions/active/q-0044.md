# Scenario
In a company, there were a lot of incidents in which the developers from a specific business unit accidentally terminated the Amazon EC2 instances owned by another business unit. A DevOps Engineer was tasked to come up with a solution to only allow a specific business unit who owns the EC2 instances and other AWS resources to terminate their own resources.

# Question
Which solution should the DevOps Engineer implement?

# Options
1. Centrally manage all of your accounts using a multi-account aggregator in AWS Config and AWS Control Tower. Configure AWS Config to allow access to certain Amazon EC2 instances in production per business unit. Launch the Customizations for AWS Control Tower (CfCT) in the different account where your AWS Control Tower landing zone is deployed. Configure the CfCT to only allow a specific business unit that owns the EC2 instances and other AWS resources to terminate their own resources.
2. Centrally manage all of your accounts using AWS Organizations. Group your accounts, which belong to a specific business unit, to individual Organization Units (OU). Set up an IAM Role in the production account which has a policy that allows access to the EC2 instances including resource-level permission to terminate the instances owned by a particular business unit. Associate the cross-account access and the IAM policy to every member accounts of the OU.

# Explanation
Use AWS Organizations with OUs per business unit and an IAM role in the production account whose policy grants resource-level permission to terminate only that unit's instances, shared via cross-account access. The Config aggregator is only a data-collection resource type, and Customizations for AWS Control Tower (CfCT) must be deployed in the same Region/account as the Control Tower landing zone.
