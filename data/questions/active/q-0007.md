# Scenario
A regional API Gateway in the us-east-2 region serves as a proxy to a backend service. Clients connect using the invoke URL of the API stage. The company wants to associate a custom domain name (api.tutorialsdojo.com) with the API, and the domain must support HTTPS. The company has an existing hosted zone for its domain on Route 53.

# Question
Which of the following would be the next step to achieve the company's objective?

# Options
1. Request a public certificate in the us-east-2 region for api.tutorialsdojo.com using AWS Certificate Manager (ACM). Create a regional API Gateway domain name and associate it with api.tutorialsdojo.com and the ACM certificate. In Route 53, create an alias record for api.tutorialsdojo.com that points to the API Gateway domain name.
2. Import an existing public certificate for api.tutorialsdojo.com into AWS Certificate Manager (ACM) in us-east-2. In Route 53, create a CNAME record for api.tutorialsdojo.com that points to the invoke URL of the API Gateway stage.
3. Request a public certificate in the us-east-1 region for api.tutorialsdojo.com using AWS Certificate Manager (ACM). Create a regional API Gateway domain name and associate it with api.tutorialsdojo.com and the ACM certificate. In Route 53, create an alias record for api.tutorialsdojo.com that points to the API Gateway domain name.
4. Use the AWS Certificate Manager Private Certificate Authority (ACM PCA) to generate a private certificate for api.tutorialsdojo.com. Override the invoke URL using stage variables.

# Explanation
For a regional API Gateway, the ACM certificate must be requested in the SAME region as the API (us-east-2). Then create a regional custom domain name in API Gateway and an alias record in Route 53. Edge-optimized endpoints would need the cert in us-east-1, but this is regional. Private certificates are for internal networks only.
