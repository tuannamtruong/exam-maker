# Scenario
A company hosts its staging website using an EC2 instance backed with EBS storage. The company wants to recover quickly with minimal data losses in the event of network connectivity issues or power failures on the EC2 instance.

# Question
Which solution will meet these requirements?

# Options
1. Add the instance to an EC2 ASG with the minimum, maximum, and desired capacity set to 1.
2. Create a CloudWatch alarm for the StatusCheckFailed System metric and select the EC2 action to recover the instance.
3. Create a CloudWatch alarm for the StatusCheckFailed Instance metric and select the EC2 action to reboot the instance.

# Explanation
The EC2 Recover action automatically migrates the instance to healthy hardware. It preserves the Instance ID, Private IP, Elastic IP, EBS volumes, and Metadata. 
This results in minimal downtime and essentially no EBS data loss because the EBS volumes remain attached after recovery.

1. It does not specifically recover from host hardware failures. New instance boot time is generally longer than EC2 Recovery. ASG is primarily for availability, not host recovery.
3. StatusCheckFailed_Instance indicates problems inside the guest OS. Reboot simply restarts the operating system on the same host. If the underlying host has lost power or networking, rebooting will not fix the problem.
