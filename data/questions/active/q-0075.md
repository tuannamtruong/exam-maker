# Scenario
Organizations to manage multiple AWS accounts grouped into several OUs. Breach in the environment where a third-party AWS account was suddenly added to the organization without prior approval.

# Question
MOST appropriate monitoring setup that notifies of any changes to the AWS accounts?

# Options
1. Create a CloudWatch Dashboard to monitor any changes to your organization. Launch a new SNS topic that will notify you and your team.
2. Use the Systems Manager and EventBridge to monitor all organizational changes and notify you of any new activities or configurations made to your account.
3. Monitor the compliance of your Organizations using Config. Launch a new SNS Topic or EventBridge rule to send alerts for any changes.
4. Launch a new trail in CloudTrail to capture all API calls to your Organizations, including calls from the Organizations console. Also, track all code calls to the Organizations APIs. Integrate EventBridge and SNS to raise events when administrator-specified actions occur in an organization and configure it to send a notification.

# Explanation
Multi-account, multi-region data aggregation in Config enables you to aggregate Config data from multiple accounts and regions into a single account. An aggregator is a new resource type in Config that collects Config data from multiple source accounts and regions.

1. a CloudWatch Dashboard is primarily used to monitor your AWS resources and not the configuration of your Organizations. While dashboards offer visualization, they are not tailored for detecting specific API calls or account additions.
2. Systems Manager is a collection of capabilities for configuring and managing your EC2 instances, on-premises servers and virtual machines, and other AWS resources at scale. This can't be used to monitor the changes to the set up of Organizations.
