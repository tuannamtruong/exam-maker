# Scenario
A company leverages API Gateway REST API to streamline SDK generation and simplify distribution to its partners. Employing an AWS CodePipeline pipeline, updates are made to the REST API multiple times daily. In the event of a deployment failure, the REST API reverts to the previous version, ensuring continuous service. However, engineers still have to manually upload corresponding SDKs to an Amazon S3 bucket. The company wants to eliminate this manual process as it is quite error-prone.
Which option will fit the requirements?

# Options
1.	Create a Lambda function to generate and download the SDKs via API Gateway GetSdk and upload them to Amazon S3. Set up an EventBridge rule to filter for API Gateway UpdateStage operation and to invoke the function on such event. 
2.	Create a Lambda function to download the generated SDKs via API Gateway GetSdk and upload them to Amazon S3. Set up a separate CodePipeline action to invoke the function. Configure the new action to be triggered by a deploy action failure. 


# Explanation
The API Gateway REST API offering includes several features that make the distribution and operation of APIs more scalable (generation of client SDKs via its GetSdk API).

Another useful feature is that API operations, such as UpdateStage create observable lifecycle events, allowing for effects, like retrieving SDKs and uploading them to S3 in this scenario, to be programmatically triggered and decoupled.
Deployment fails-> Rollback occurs-> Stage updated back to previous deployment-> UpdateStage event emitted-> Lambda generates SDK-> SDK matches rolled-back API  
This solution is state-based, not pipeline-based.

SDK generation must happen after successful deployment event, not as part of pipeline execution steps.

2. because CodePipeline does not provide a feature for conditional actions. A pipeline action can be retried if it fails at some stage but, in general, a pipeline only “moves forward” and either succeeds or fails.
