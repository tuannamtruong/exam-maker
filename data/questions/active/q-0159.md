# Scenario
A REST API invokes a Lambda function.

Lambda loads a large amount of data during initialization.
Cold starts take 8–10 seconds.
DynamoDB already uses DAX.
Traffic varies dramatically:
Normal traffic
Midday: 10× higher
End of day: 10% of normal

# Question
Minimize Lambda latency throughout the day.

# Options
1. Configure provisioned concurrency on the Lambda function with a concurrency value of 1. Delete the DAX cluster for the DynamoDB table.
2. Configure reserved concurrency on the Lambda function with a concurrency value of 0.
3. Configure provisioned concurrency on the Lambda function. Configure Application Auto Scaling on the Lambda function with provisioned concurrency values set to a minimum of 1 and a maximum of 100.
4. Configure reserved concurrency on the Lambda function. Configure Application Auto Scaling on the API Gateway API with a reserved concurrency maximum value of 100.

# Explanation
Provisioned Concurrency keeps execution environments already initialized.
1. During a 10× traffic spike, Lambda still creates many new environments, causing cold starts.
Deleting DAX would likely increase initialization time.
2. Disable the Lambda function completely.
4. API Gateway does not have reserved concurrency.
