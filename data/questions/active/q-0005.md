# Scenario
A company must integrate the LDAP directory service from the on-premises data center to the AWS VPC using IAM. The identity store currently being used is not compatible with SAML.

# Question
Which of the following provides the most valid approach to implement the integration?

# Options
1. Use an IAM policy that references the LDAP identifiers and AWS credentials.
2. Use IAM roles to rotate the IAM credentials whenever LDAP credentials are updated.
3. Develop an on-premises custom identity broker application and use STS to issue short-lived AWS credentials.
4. Use AWS IAM Identity Center to manage access between AWS and your LDAP.

# Explanation
1. simply using an IAM policy is not enough to integrate your LDAP service to IAM. You need to use SAML, STS, or a custom identity broker.
2. manually rotating the IAM credentials is not an optimal solution to integrate your on-premises and VPC network. You need to use SAML, STS, or a custom identity broker.
4. While AWS IAM Identity Center can integrate with external identity providers, it primarily supports SAML 2.0-based identity providers. The question explicitly states that the identity store is not compatible with SAML.
