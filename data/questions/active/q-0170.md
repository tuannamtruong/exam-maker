# Scenario
The stack update process failed due to an error in the updated template, and AWS CloudFormation automatically began the stack rollback process.
The stack was in the UPDATE_ROLLBACK_FAILED state.

# Question
TWO

# Options
1.	Attach the AWSCloudFormationFullAccess IAM policy to the AWS CloudFormation role. 
2.	Automatically recover the stack resources by using AWS CloudFormation drift detection. 
3.	Issue a ContinueUpdateRollback command from the AWS CloudFormation console or the AWS CLI. 
4.	Manually adjust the resources to match the expectations of the stack. 
5.	Update the existing AWS CloudFormation stack by using the original template.

Before CloudFormation can continue, you must resolve the resource issue.
Once the underlying issue is fixed, CloudFormation does not automatically resume. You must issue: ContinueUpdateRollback.
