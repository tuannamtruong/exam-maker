# Scenario
Notified of any S3 bucket policy changes to identify and take action if any problem occurs quickly.

# Question
Which of the following options will help achieve this?

# Options
1. Create a CloudTrail trail that sends logs to a CloudWatch log group. Create an EventBridge rule for S3 bucket policy events on the log group. Create an Alarm based on the event that will send you a notification whenever an event is matched.
2. Enable S3 server access logging on your bucket. Send the access logs to a CloudWatch log group. Create a CloudWatch Metric Filter for bucket policy events on the log group. Create an Alarm for this metric to notify you whenever the threshold is reached.
3. Create a CloudTrail trail that sends logs to a CloudWatch log group. Create a CloudWatch Metric Filter on the log group for S3 bucket policy events. Create an Alarm that will notify you whenever this metric threshold is reached.

# Explanation
Since all CloudTrail events will be sent to the Log group, you will need to create a Metric to filter specific S3 events that change the bucket policy of your bucket. For notification, you will then create a CloudWatch Alarm for this Metric with a threshold of >=1 and set your email as a notification recipient.

1. You can't simply use an EventBridge rule to filter your log groups directly.
2. S3 Server access logging is primarily used to provide detailed records for the requests that are made to a bucket. Each access log record provides details about a single access request (requester, bucket name...). It is more appropriate to use CloudWatch or CloudTrail to track the S3 bucket policy changes. You can't directly send the S3 server access logs to CloudWatch logs. You need to use CloudTrail to send the events to a log group before you can create a metric and alarm for those events.
