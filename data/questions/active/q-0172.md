# Scenario
A company publishes VPC Flow Logs to CloudWatch Logs.

The company needs to:
>continuously monitor network traffic
>detect anomalies over time
>automatically initiate a response when anomalies are detected

# Options
1.	Create a Kinesis Data Stream. Subscribe the CloudWatch Logs log group to the stream. Configure Kinesis Data Analytics to detect anomalies. Configure a Lambda function as the output of the analytics application. When an anomaly is detected, the Lambda function publishes an event to the default EventBridge event bus. 
2.	Create a Kinesis Data Firehose delivery stream to S3. Subscribe the log group to Firehose. Configure Lookout for Metrics to monitor the S3 data. Configure a Lambda function to respond to anomaly findings and publish events to EventBridge. 
3.	Subscribe a Lambda function directly to the CloudWatch Logs log group. Implement anomaly detection inside the Lambda function. Publish an EventBridge event when an anomaly is detected. 
4.	Create a Kinesis Data Stream. Subscribe the log group to the stream. Configure a Lambda function as the stream processor. Implement anomaly detection inside the Lambda function. Publish an EventBridge event when an anomaly is detected.

# Explanation
VPC Flow Logs -> CloudWatch Logs -> Kinesis Data Stream -> Kinesis Data Analytics -> Lambda -> EventBridge -> Response workflow
Kinesis Data Analytics is designed for real-time stream analytics. It can continuously analyze streaming data and detect unusual patterns over time, making it well suited for streaming VPC Flow Logs.

2. Firehose is not intended for streaming analytics
3. A Lambda function can process log events, but it does not provide built-in anomaly detection.
4. Kinesis Data Streams with Lambda is a common pattern for event processing, but Lambda is still responsible for implementing all anomaly detection logic.
The question specifically asks for identifying anomalies over time, which is better handled by a managed analytics service than custom Lambda code.
