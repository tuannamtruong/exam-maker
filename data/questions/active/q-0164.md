# Scenario
About 10% of records are invalid and require manual processing.
Lambda processes records in batches.
Lambda retries failed batches.
An SQS dead-letter queue is configured as the on-failure destination.
The problem is that many valid records, which were already successfully processed by the REST API, also end up in the DLQ.

# Question
minimize the number of valid records sent to the DLQ.

# Options
1.	Increase the retry attempts. 
2.	Configure the setting to split the batch when an error occurs. 
3.	Increase the concurrent batches per shard. 
4.	Decrease the maximum age of record.

# Explanation
If the function fails because of one bad record, Lambda treats the entire batch as failed. 
With BisectBatchOnFunctionError enabled, only the small portion containing the bad record continues to be retried.

1. More retries simply mean the same batch is retried more times.
3. Increase throughput, irrelevant.
4. Reducing it causes failures to reach the DLQ sooner, but it does not reduce the number of valid records that accompany a failed batch.
