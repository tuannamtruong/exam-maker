# Scenario
A DevOps engineer is responsible for updating golden image AMIs used in its ECS clusters through CloudFormation. A solution is required to ensure a streamlined process that includes version control of the AMI build spec and stack source/s and facilitates peer review for stakeholders. The solution must also keep the building of the AMI from its configuration into the ECS clusters decoupled.

# Question
Which set of steps will meet these requirements? (Select THREE.)

# Options
1. Set up a CloudFormation action that deploys/updates the stack with an updated version of the golden image. In the same pipeline, set the image version as an output variable from the CodeBuild action that builds the image.
2. Set up a GitHub repository to host the build spec and stack source code. Establish a CodePipeline pipeline with the GitHub repository as its source.
3. Set up a GitHub repository each for the AMI build spec and for the CloudFormation stack source code.
4. Establish a CodePipeline pipeline with the AMI build spec repository as its source. In this pipeline, set up a CodeBuild action that builds the golden image.
5. Configure a CodePipeline pipeline with the CloudFormation stack repository as its source. Set up a CloudFormation action to apply.
6. Set up an action for a Lambda function to sync changes to the CloudFormation stack.

# Explanation
In this scenario, 2 independent CodePipeline pipelines are triggered by 2 independent (by design) events:
1. a change in the build spec of the AMI
2. a change in the CloudFormation stack source
The output of the first one being the golden image AMI and that of the second one being the CloudFormation stacks with the updated golden image.

1. Chaining the CloudFormation deploy into the same pipeline as the CodeBuild image build and passing the image version between them as an output variable is exactly the coupling the requirements forbid.
2. Hosting both the build spec and the stack source code in a single repository with a single pipeline as its source couples the two concerns; any commit to either one triggers the whole pipeline.
6. Lambda would be just unnecessary overhead in this scenario not to use the native CloudFormation action format.
