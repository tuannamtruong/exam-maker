# Scenario
A company wants to redirect directory requests to its on-premises Microsoft AD without caching any information in AWS. The DevOps Engineer set up AD Connector through custom resource in AWS CloudFormation. The AD Connector was created via the Lambda function, but CloudFormation is not moving from the state of CREATE_IN_PROGRESS to CREATE_COMPLETE.

# Question
Which of the following is the MOST suitable solution should the DevOps Engineer take?

# Options
1. Confirm that the Lambda function code has exited successfully.
2. Make sure that the IAM role assigned to the Lambda function has cloudformation:UpdateStack permissions for the stack’s ARN.
3. Make sure that the pre-signed URL obtains a response from the Lambda function code.
4. Confirm that the AWS account’s IAM role associated with the Lambda function has ds:ConnectDirectory permissions.

# Explanation
When a custom resource invokes a Lambda function, CloudFormation passes a pre-signed URL and waits for the function to send a response to it. If the function never responds, the stack stays in CREATE_IN_PROGRESS regardless of whether the code exited successfully or the AD Connector was created. cloudformation:UpdateStack and ds:ConnectDirectory permissions don't resolve the missing response.
