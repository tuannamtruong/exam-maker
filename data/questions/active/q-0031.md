# Scenario
A company operates a data lake on S3 with Apache Parquet data from various sources. To enhance the data, the company employs multiple transformation steps: filtering anomalies, standardizing date and time formats, and generating analytical aggregates. The transformed data is stored in S3 buckets for data analysts. The company seeks a pre-built, non-coding solution for these data transformations, with data lineage and profiling features, and the transformation steps must be transparent and shareable across the organization.

# Question
What is the most suitable AWS solution?

# Options
1. Query data using Athena to execute the data transformation using SQL queries. Facilitate the sharing of these Athena SQL queries among employees.
2. Utilize AWS Glue DataBrew for the data transformation tasks. Make the transformation steps available to employees through the use of DataBrew recipes.
3. Leverage AWS Glue Studio's visual interface for data transformation. Distribute the transformation process across the organization by utilizing AWS Glue jobs.
4. Set up EMR to manage data transformation. Document and share the transformation steps with employees through EMR Studio notebooks.

# Explanation
AWS Glue DataBrew is a no-code visual data prep tool with built-in data lineage and profiling. Transformation steps are saved as DataBrew recipes that can be shared. Glue Studio is visual but lacks DataBrew's lineage/profiling. Athena is SQL-based. EMR Studio requires technical expertise.
