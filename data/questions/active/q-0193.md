# Scenario
A company manually provisions IAM access for its employees. The company wants to replace the manual process with an automated process. The company has an existing Active Directory system configured with an external SAML 2.0 identity provider (IdP).

The company wants employees to use their existing corporate credentials to access AWS. The groups from the existing Active Directory system must be available for permission management in Identity and Access Management (IAM). A DevOps engineer has completed the initial configuration of IAM Identity Center (Single Sign-On) in the company's AWS account.

# Question
What should the DevOps engineer do next to meet the requirements?

# Options
1. Configure an external IdP as an identity source. Configure automatic provisioning of users and groups by using the SCIM protocol.
2. Configure Directory Service as an identity source. Configure automatic provisioning of users and groups by using the SAML protocol.
3. Configure an AD Connector as an identity source. Configure automatic provisioning of users and groups by using the SCIM protocol.
4. Configure an external IdP as an identity source. Configure automatic provisioning of users and groups by using the SAML protocol.

# Explanation
key sentence "The company has an existing Active Directory system configured with an external SAML 2.0 identity provider (IdP)."
This tells you the authentication flow already exists.

- Authentication (letting employees log in with corporate credentials) is handled by SAML 2.0 — that's the trust between IAM Identity Center and the external IdP.
- Provisioning. IAM Identity Center also needs to know: users, groups, group membership. it uses SCIM instead of SAML.

In this question, the users' accounts originate from Active Directory, but authentication is delegated to an external SAML IdP. Therefore, the correct identity source for IAM Identity Center is the external IdP

2. Directory Service isn't the identity source here (they already have an external SAML IdP), and SAML doesn't provision groups.
3. AD Connector is for a self-managed AD on-prem, not for an external SAML IdP; wrong identity source.
4. Correct identity source, but SAML can't do provisioning; you need SCIM for the groups to appear in IAM Identity Center.
