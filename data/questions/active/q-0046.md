# Question
A DevOps team runs a microservices application on an Amazon EKS cluster. They need to implement a solution that automatically scales the number of pods for a specific deployment based on CPU utilization. They also want to ensure the underlying cluster has enough EC2 nodes to run these pods. Which components should they implement? (Select TWO.)

# Options
1. The Horizontal Pod Autoscaler (HPA)
2. The Cluster Autoscaler
3. The Vertical Pod Autoscaler (VPA)
4. The Kubernetes scheduler
5. An Amazon EC2 Auto Scaling group

# Explanation
The Horizontal Pod Autoscaler scales the number of pods based on observed CPU utilization, and the Cluster Autoscaler adjusts the number of nodes in the EKS node group so there is room to schedule those pods. The VPA scales a pod's CPU/memory reservations (not pod count) and can't be used with HPA on the same metric; the Kubernetes scheduler only assigns pods to nodes; and managing the EC2 Auto Scaling group directly is not Kubernetes-aware.
