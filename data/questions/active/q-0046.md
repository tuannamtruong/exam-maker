# Question
A DevOps team runs a microservices application on an Amazon EKS cluster. They need to implement a solution that automatically scales the number of pods for a specific deployment based on CPU utilization. They also want to ensure the underlying cluster has enough EC2 nodes to run these pods. Which components should they implement? (Select TWO.)

# Options
1. The Horizontal Pod Autoscaler (HPA)
2. The Cluster Autoscaler
3. The Vertical Pod Autoscaler (VPA)
4. The Kubernetes scheduler
5. An Amazon EC2 Auto Scaling group

# Explanation
The HPA is a standard Kubernetes component that automatically scales the number of pods in a replication controller, deployment, replica set, or stateful set based on observed CPU utilization or other select metrics. This directly addresses the requirement to scale the application pods.

The Cluster Autoscaler for AWS automatically adjusts the number of nodes in your EKS cluster's node group. When the Horizontal Pod Autoscaler needs to schedule more pods than can fit on the existing nodes, the Cluster Autoscaler will provision new nodes. It also removes underutilized nodes to save costs.

3. The VPA automatically adjusts the CPU and memory reservations for pods to match their actual usage. It scales the resources allocated to a pod (scaling up/down), rather than scaling the number of pods (scaling out/in). It cannot be used at the same time as the HPA on CPU or memory.
4. The Kubernetes scheduler is a core component responsible for assigning newly created pods to nodes that can satisfy the pod's resource requirements. It does not, however, have the ability to scale the number of pods or the number of nodes in the cluster.
5. While the EKS nodes run within an EC2 Auto Scaling group, managing this group directly with traditional EC2 scaling policies would not be Kubernetes-aware. The Cluster Autoscaler is the proper tool to manage the size of the node group based on the pod scheduling needs of the Kubernetes cluster.
