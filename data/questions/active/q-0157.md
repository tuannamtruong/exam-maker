# Scenario
Legacy API runs on EC2 behind one public ALB.
ALB access logs must remain unchanged because another service processes them.
Only five endpoints have been rewritten as Lambda functions.
A small percentage of random users should test the new implementation


# Options
1. Add the five Lambda functions as targets to the existing target group for the EC2 instances. Set the weight in the target group of each Lambda function target to be less than the EC2 instance targets. Amend the default rule on the ALB to enable target group-level stickiness. 
2. Create a single target group that includes all the Lambda functions as individual targets. On the ALB, create a new listener rule that includes a host header condition that matches the API endpoint’s hostname. Add the target group to the listener rule. Specify a lower weight for the new target group than the weight of the default rule’s target group. 
3. Create a new ALB and a new target group for each Lambda function. Create a new listener rule that includes a host header condition that matches each of the endpoints and forwards traffic to the target groups. Create a new Route 53 alias record with a weight of 10. Update the existing Route 53 record for the api.example.com hostname with a weight of 90. 
4. Create a new target group for each Lambda function. On the ALB, create new listener rules that include a path condition that matches each of the different endpoints. Set the rules to be weighted between the Lambda function target group for that endpoint and the instance-based target group

# Explanation
You cannot register multiple Lambda functions to a single target group.
