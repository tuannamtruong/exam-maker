# Scenario
A company deployed AWS resources by using an AWS CloudFormation template. The template specified only the properties necessary for the resource creation. The template inherited the default values for the remaining optional properties. To deploy the workload with proper configuration, the company had to reconfigure the default values outside of CloudFormation. The reconfiguration led to configuration inconsistencies.
The company wants to maintain all the settings for the properties through the template. The company wants to identify any changes made outside of CloudFormation and remediate the template back to the original configuration.

# Question
LEAST implementation effort?

# Options
1. Update the template to specify resource configuration values for all properties, including default values. Use the cloudformation-stack-drift-detection-check AWS Config rule. Configure the rule’s automatic remediation action to run the AWS-UpdateCloudFormationStack AWS Systems Manager Automation runbook.
2. Use the cloudformation-stack-drift-detection-check AWS Config rule. Configure the rule’s automatic remediation action to run the AWS-UpdateCloudFormationStack AWS Systems Manager Automation runbook.

# Explanation
Req 1: CloudFormation must manage every property
Example: If someone later enables Versioning manually, CloudFormation cannot restore it because Versioning was never part of the template.
Therefore the template must explicitly specify all desired properties, including values that happen to match AWS defaults, to have CloudFormation track a resource property to determine drift.

Reg 2: Detect and remediate drift -> Config + SSM Automation.

2. You must explicitly specify a property value, even if it is the default value, to have CloudFormation track a resource property to determine drift. You must specify all resource properties by using CloudFormation. Otherwise, CloudFormation cannot maintain all the properties of the settings.
