# Scenario
A company is running an on-premises application backed by a 1TB MySQL 8.0 database. Each month, the production data is fully copied to a staging database at the request of the analytics team. The team can't work on staging until the copy is finished (which takes hours), and the application experiences intermittent downtimes during the copy. To expedite the process, a solutions architect must redesign the application's architecture in AWS. The application must also be highly resilient to disruptions.

# Question
Which combination of actions best satisfies the given set of requirements while being the most cost-effective? (Select TWO.)

# Options
1. Use an RDS database in a Multi-AZ Deployments configuration.
2. Use an Aurora database with Multi-AZ Replicas.
3. Replicate the production database to a staging database using the mysqldump client utility.
4. Take a manual snapshot and restore it to a database in the staging environment.
5. Clone the production database in the staging environment using Aurora cloning.

# Explanation
Aurora with Multi-AZ Replicas provides high resiliency. Aurora cloning creates a copy-on-write clone almost instantly without impacting the source — far faster and cheaper than mysqldump or snapshot/restore.
