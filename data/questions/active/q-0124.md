# Scenario
The DevOps team’s group has a permission set named tdDevOps, which includes the AdministratorAccess policy.
This permission set is applied to all accounts under the organization. The SecOps team must ensure that DevOps engineers cannot modify or view IAM Identity Center configurations in the management account.
"Action": [
    "sso:*",
    "sso-directory:*"
],
"Resource": "*",
"Condition": {
    "ArnLike": {
        "aws:PrincipalARN": [
            "arn:aws:iam::*:role/AWSReservedSSO_tdDevOps_*"
        ]
    }
}
Despite the SCP, DevOps users can still access the IAM Identity Center in the management account.

# Question
Fix?

# Options
1. Modify the DevOps permission set in the IAM Identity Center to allow full access while denying the actions sso:* and sso-directory:*. Add a StringEquals condition in the Deny statement to compare aws:SourceAccount with the management account ID. Lastly, remove the Service Control Policy (SCP).
2. Create a new IAM policy that explicitly denies sso:* and sso-directory:* actions for the DevOps team’s group role. Attach this policy to the DevOps team’s group role and the AdministratorAccess policy.

# Explanation
SCPs apply only to users, roles, and groups in member accounts, not to management account administrators or IAM Identity Center users unless configured carefully. In this case, the SCP was configured with a condition targeting the tdDevOps permission set.

To resolve this issue, modifications need to adjust the permission set configurations in the IAM Identity Center to explicitly deny the required actions. Additionally, by adding a condition to restrict access based on the source account, you can ensure that the deny statement only applies to the management account.

2. IAM policies cannot override the higher-level permissions granted by the IAM Identity Center permission set.
