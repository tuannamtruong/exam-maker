# Scenario
A company wants to employ a new standard that requires the creation of resources through CloudFormation. Due to this, IT administrators need to make sure that users can only deploy stacks from pre-approved CloudFormation templates.

# Options
1. Use Service Catalog with launch constraint to authorize users to deploy CloudFormation stacks.
2. Use Service Catalog with template constraint to authorize users to deploy CloudFormation stacks.

# Explanation
A launch constraint lets Service Catalog assume an IAM role on the user's behalf when provisioning the product. That means the users themselves need almost no IAM permissions — no direct CloudFormation/EC2/S3 access — so the only way they can create resources is through the pre-approved products in the portfolio. -> "only pre-approved templates."



2. The template constraint just limits the options that are available to end-users when they launch a product. It works by narrowing the allowable values for parameters that are defined in the product’s underlying AWS CloudFormation template.
It does not control which templates a user is able to deploy.
