# Scenario
solution that collects all of the application and server logs effectively, even if the ASG immediately terminated the instance.

# Question
LEAST amount of effort?

# Options
1. Delay the termination of unhealthy EC2 instances by adding a lifecycle hook to your ASG to move instances in the Terminating state to the Terminating:Wait state. Create an EventBridge rule for the EC2 Instance-terminate Lifecycle Action Auto Scaling Event with an associated Systems Manager Automation document. Trigger the CloudWatch agent to push the application logs and then resume the instance termination once all the logs are sent to CloudWatch Logs.
2. Delay the termination of unhealthy EC2 instances by adding a lifecycle hook to your ASG to move instances in the Terminating state to the Terminating:Wait state. Use Step Functions to collect the application logs and send them to a CloudWatch Log group. Resume the instance termination once all the logs are sent to CloudWatch Logs.
3. Delay the termination of unhealthy EC2 instances by adding a lifecycle hook to your ASG to move instances in the Terminating state to the Pending:Wait state. Create an EventBridge rule for the EC2 Instance-terminate Lifecycle Action Auto Scaling Event with an associated Lambda function. Use the Systems Manager Automation to run a script that collects and uploads the application logs from the instance to a CloudWatch Logs group. Resume the instance termination once all the logs are sent.
4. Delay the termination of unhealthy EC2 instances by adding a lifecycle hook to your ASG to move instances in the Terminating state to the Terminating:Wait state. Create an EventBridge rule for the EC2 Instance Terminate Successful Auto Scaling Event with an associated Lambda function. Use the Systems Manager Run Command to run a script that collects and uploads the application logs from the instance to a CloudWatch Logs group. Resume the instance termination once all the logs are sent.

# Explanation
A lifecycle hook that moves the instance to the Terminating:Wait state pauses termination long enough to collect the logs. An EventBridge rule for the EC2 Instance-terminate Lifecycle Action event triggers a Systems Manager Automation document that runs the CloudWatch agent to push the application and server logs to CloudWatch Logs, then resumes termination once the logs are sent. This collects the logs reliably with the least amount of effort.

2. using Step Functions is inappropriate when collecting the logs from your EC2 instances. You should use a CloudWatch agent instead.
3. the Pending:Wait state simply refers to the scale-out action in EC2 Auto Scaling and not for scale-in or for terminating the instances.
4. The EC2 Instance Terminate Successful indicates that the ASG has terminated an instance. The automated solution won't just work because the target instance is already deleted when the Lambda function is triggered.
