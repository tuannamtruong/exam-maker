# Scenario
Users experience significant latency whenever they log into the site. There are times when their users get HTTP 504 errors in the login process.

# Question
Which solution improves performance with MINIMAL costs?

# Options
1. Create an origin group with two origins to set up an origin failover in CloudFront. Specify one as the primary origin and the other as the second origin. This configuration will cause the CloudFront service to automatically switch to the second origin in the event that the primary origin returns specific HTTP status code failure responses.
2. Use Lambda@Edge to customize the content that the CloudFront distribution delivers to your users across the globe. This will allow the Lambda functions to execute the authentication process in a specific location that is proximate to the user.
3. Replicate your application stack to multiple regions to serve your users around the world. Set up a Route 53 record with Latency routing policy that will automatically route traffic to the region with the best latency to the user.
4. Deploy your application stack to multiple and geographically disperse VPCs on various regions. Set up a Transit VPC to easily connect all your VPCs and resources. Using the Serverless Application Model (SAM) service, deploy several Lambda functions in each region to improve the overall application performance.

# Explanation
CloudFront automatically switches to the second origin when the primary origin fails. This will alleviate the occasional HTTP 504 errors that users are experiencing.

3. Although this may resolve the performance issue, this solution entails a significant implementation cost since you have to deploy your application to multiple regions. Remember that the scenario asks for a solution that will improve the performance of the application with minimal cost.
4. Although setting up multiple VPCs across various regions which are connected with a transit VPC is valid, this solution still entails higher setup and maintenance costs. A more cost-effective option would be to use Lambda@Edge instead.
