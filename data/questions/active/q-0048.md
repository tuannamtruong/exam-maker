# Scenario
A DevOps engineer is designing a highly scalable and resilient architecture to process images uploaded by users. The workflow requires that upon upload, each image is resized into multiple formats and then archived. The volume of uploads is highly variable, ranging from a few per hour to thousands per second.

# Question
Which combination of AWS services should the engineer use to provide the most scalable and decoupled solution for this workflow? (Select THREE.)

# Options
1. S3
2. SQS
3. AWS Lambda
4. Kinesis Data Streams

# Explanation
S3 is the ideal service for storing the uploaded images. It is highly durable, scalable, and can be configured to trigger events upon object creation. An S3 PutObject event can serve as the starting point for the entire processing workflow.

Using an SQS queue to decouple the image upload from the processing steps is a key design pattern for resilience and scalability. An S3 event can publish a message to an SQS queue. This allows the processing tasks to be handled asynchronously and ensures that processing jobs are not lost if a downstream service fails temporarily.

AWS Lambda is perfectly suited for the event-driven processing tasks. A Lambda function can be triggered by the S3 event or by messages arriving in the SQS queue. Lambda automatically scales to handle the number of incoming events, executing the image resizing logic in parallel for each uploaded image without the need to manage servers.

4. Kinesis Data Streams is designed for real-time streaming data and is typically used when the order of records is important or when multiple consumers need to process the same stream of data. For a job-based workload like image processing, where each job is independent, SQS is a simpler and more cost-effective choice.
