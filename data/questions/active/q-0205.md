# Scenario
A development AWS account has EC2 instances with security groups that allow SSH (port 22) from 0.0.0.0/0.

Requirements:

Detect these security issues.
Notify administrators when Trusted Advisor finds them.
Automatically remediate the security group by restricting SSH to the corporate public IP. (Select THREE.)

# Options
1. Set up custom Config rule that checks security groups to make sure that port 22 is not open to public. Send a notification to an SNS topic for non-compliance.
2. Create a Lambda function that executes every hour to refresh Trusted Advisor scan results via API. The automated notification on Trusted Advisor will notify of any changes.
3. Create a Lambda function and integrate EventBridge and Lambda to execute the function on a regular schedule to check Trusted Advisor via API. Based on the results, publish a message to an SNS Topic to notify the subscribers.
4. Set up a custom Config rule to execute a remediation action using Systems Manager Automation to update the security group rules for port 22 and restrict it to the office's public IP.
5. Create a Config Cron job to schedule checks on all security groups and send results to SNS for the non-compliance notification.
6. Set up custom Config rule to execute a remediation action that triggers a Lambda Function to update the publicly open port 22 in the security group and restrict to the office's public IP.

# Explanation
2. The notification is only sent on a weekly basis, which can be quite long if you are concerned about security issues.
5. You do not schedule Config with Cron jobs since this service can be configured to run periodically.
6. The custom remediation actions in Config is simply used in conjunction with Systems Manager Automation documents.
