# Scenario
A corporation has several Windows file servers across departments in its on-premises data center. To improve data management and scalability, it must migrate and integrate its files into an FSx for Windows File Server file system while keeping the current file permissions intact.

# Question
Which solutions will fulfill the company's requirements? (Select TWO.)

# Options
1. Utilize the AWS CLI to copy the file shares from each on-premises file server to an S3 bucket. Then, schedule AWS DataSync tasks to move the data from S3 to the FSx for Windows File Server file system.
2. Use AWS Storage Gateway to create a file gateway, then mount the file gateway on the on-premises file servers. Migrate the data from the file servers to the file gateway, and then use AWS DataSync to move the data from the file gateway to the FSx for Windows File Server file system.
3. Acquire an AWS Snowcone device, then connect with the on-premises network. Use AWS OpsHub to launch the AWS DataSync agent AMI and activate the agent via the AWS Management Console. Schedule DataSync tasks to transfer the data to the FSx for Windows File Server file system.
4. Order an AWS Snowball Edge Storage Optimized device, link it to the on-premises network, and transfer data using the AWS CLI. Return the device to AWS for data import into S3. Configure AWS DataSync tasks to migrate the data from S3 to the FSx for Windows File Server file system.
5. Set up AWS DataSync agents on the corporation's on-premises file servers and schedule DataSync tasks for transferring data to the FSx for Windows File Server file system.

# Explanation
DataSync (with on-prem agents or via Snowcone in remote locations) transfers SMB shares to FSx for Windows File Server while preserving ACLs. Going through S3 (CLI or Snowball) adds unnecessary steps and doesn't reliably preserve Windows permissions. Storage Gateway file gateway is for hybrid storage, not direct migration.
