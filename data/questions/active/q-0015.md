# Scenario
A company has a fleet of Spot EC2 instances behind an ALB. The incoming traffic comes from users across multiple AWS regions, and the user's session should be shared among the fleet of instances. Set up a distributed session management layer providing scalable and shared data storage for the user sessions that supports multithreaded performance. The cache layer must also detect any node failures and replace the failed ones automatically.

# Question
Which of the following would be the best choice while still providing sub-millisecond latency for the users?

# Options
1. AWS ELB sticky sessions
2. ElastiCache for Memcached with Auto Discovery
3. ElastiCache for Redis Global Datastore
4. RDS database with RDS Proxy

# Explanation
ElastiCache for Memcached supports multithreaded performance and Auto Discovery (clients automatically learn all cluster nodes, and failed nodes are detected and replaced). Redis is single-threaded by default. ELB sticky sessions pin users to a server (not what's needed when state is shared). RDS is far higher latency.
