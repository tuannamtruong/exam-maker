# Scenario
A web application is served through Amazon CloudFront. The primary origin is an S3 bucket configured for website hosting in us-east-1. A second S3 bucket in us-west-2 serves as a backup.

# Question
How can a DevOps engineer configure CloudFront to automatically serve content from the backup bucket if the primary bucket becomes unavailable? (Select TWO.)

# Options
1. Create an origin group with the primary S3 bucket as the primary origin and the backup S3 bucket as the secondary origin.
2. Configure the origin group to fail over when the primary origin returns 5xx responses or selected 4xx codes.
3. Use a Lambda@Edge function to check the health of the primary origin and rewrite the request to the secondary origin if it fails.
4. Configure a latency-based routing policy in Amazon Route 53 for the origin domain name.
5. Enable S3 Cross-Region Replication from the primary to the secondary bucket.

# Explanation
CloudFront origin groups are the feature designed specifically for origin failover. You can group two origins, designate one as primary, and CloudFront will automatically switch to the secondary origin upon specific HTTP error status codes from the primary.

When you create a CloudFront origin group, you must specify the conditions that trigger failover. Typically, you configure the group to fail over when the primary origin responds with HTTP 5xx server errors or specific 4xx client errors, such as 404 Not Found, that indicate missing or unavailable content. This configuration ensures that CloudFront automatically routes requests to the backup S3 bucket when the primary bucket is unavailable or returning error responses.

3. While it is technically possible to implement custom failover logic with a Lambda@Edge function, it is much more complex and less cost-effective than using the native CloudFront origin group feature. The built-in feature is the standard, recommended approach for this use case.
4. Route 53 policies operate at the DNS level to resolve a domain name to an IP address. CloudFront communicates directly with its configured origins (such as the S3 bucket endpoint). DNS routing policies are not used to manage failover between CloudFront origins.
5. S3 Cross-Region Replication is necessary to ensure the content exists in the backup bucket, but it does not configure CloudFront to perform the failover. It is a data-plane action, whereas the origin group configuration is a control-plane action that tells CloudFront how to route requests during a failure.
