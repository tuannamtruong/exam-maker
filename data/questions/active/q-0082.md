# Scenario
A solutions architect developed a web application that includes an API Gateway Regional endpoint and a Lambda function that queries an Aurora MySQL database. The web app users are close to the Region where the application is deployed. The database is configured with three read replicas.

During periods of high demand, the application does not meet performance requirements. Under high load, the application opens many database connections, causing a degradation in the application's performance.

# Question
Which actions should the solutions architect take to improve the performance? Select TWO.

# Options
1. Connect an RDS Proxy connection pool to the reader endpoint of the Aurora database.
2. Configure the application to use the cluster endpoint of the Aurora database.
3. Configure an Aurora Serverless database cluster and use automatic scaling.
4. Move Lambda function code for opening the database connection outside of the event handler.
5. Create a Classic Load Balancer to distribute connections across the three Aurora Read Replicas.

# Explanation
RDS Proxy reduces the number of database connections by pooling and reusing connections. Connecting it to the reader endpoint helps use the Aurora read replicas.

Lambda execution environments can be reused. Opening the database connection outside the handler allows connection reuse between invocations, reducing connection overhead.

2. the Aurora cluster endpoint points to the writer instance, not the read replicas.
3. the main issue is too many database connections, not just database capacity.
5. Classic Load Balancer is not used to distribute connections to Aurora read replicas. Aurora already provides a reader endpoint for this.
