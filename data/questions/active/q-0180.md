# Scenario

A company has a CodePipeline pipeline in the eu-west-1 Region. The pipeline stores the build artifacts in an S3 bucket. The pipeline builds and deploys a Lambda function by using a CloudFormation deploy action.

A DevOps engineer needs to update the existing pipeline to also deploy the Lambda function to the us-east-1 Region. The pipeline has already been updated to create an additional artifact to deploy to us-east-1.

# Question

Which combination of steps should the DevOps engineer take to meet these requirements? (Choose two.)

# Options

1. Modify the CloudFormation template to include a parameter for the Lambda function code's .zip file location. Create a new CloudFormation deploy action for us-east-1 in the pipeline. Configure the new deploy action to pass in the us-east-1 artifact location as a parameter override.
2. Create a new CloudFormation deploy action for us-east-1 in the pipeline. Configure the new deploy action to use the CloudFormation template from the additional artifact that was created for us-east-1.
3. Create an S3 bucket in us-east-1. Configure the S3 bucket policy to allow CodePipeline to have read and write access.
4. Create an S3 bucket in us-east-1. Configure S3 Cross-Region Replication (CRR) from the S3 bucket in eu-west-1 to the S3 bucket in us-east-1.
5. Modify the pipeline to include the S3 bucket for us-east-1 as an artifact store. Create a new CloudFormation deploy action for us-east-1 in the pipeline. Configure the new deploy action to use the CloudFormation template from the us-east-1 artifact.

# Explanation

CodePipeline runs a cross-Region action only if the pipeline has an artifact store (an S3 bucket) in that Region. Registering the us-east-1 bucket as an artifact store (option 5) is what lets CodePipeline replicate the input artifacts into us-east-1, so the new CloudFormation deploy action there has something to fetch. Once the store exists, CodePipeline copies the input artifacts into it automatically, and the new action deploys the stack from the us-east-1 artifact.

A Lambda function's deployment package (.zip) must live in an S3 bucket in the same Region as the function. CloudFormation does not automatically rewrite the AWS::Lambda::Function Code.S3Bucket / S3Key to the regional bucket, so the template cannot hardcode the eu-west-1 location — a us-east-1 stack pointed at a eu-west-1 code bucket fails.

2. Creating the deploy action alone is not enough. Without a us-east-1 artifact store the cross-Region action has nowhere to source its artifacts, and it does not address the Lambda code needing to be in the same Region as the function.

3. This only creates an orphan bucket with a policy — it is never registered in the pipeline's artifactStores, so CodePipeline never replicates artifacts into it. 

4. S3 Cross-Region Replication is not the mechanism CodePipeline uses to move artifacts across Regions.
