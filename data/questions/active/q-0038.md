# Scenario
A DevOps Engineer in a leading aerospace engineering company has a hybrid cloud architecture that connects its on-premises data center with AWS via Direct Connect Gateway. There is a new requirement to implement an automated OS patching solution for all of the Windows servers hosted on-premises as well as in AWS Cloud. The AWS Systems Manager service should be utilized to automate the patching of the servers.

# Question
Which combination of steps should be set up to satisfy this requirement? (Select TWO.)

# Options
1. Set up several IAM service roles for AWS Systems Manager to enable the service to execute the STS AssumeRoleWithSAML operation. Allow the generation of service tokens by registering the IAM role. Use the service role to perform the managed-instance activation.
2. Download and install the SSM Agent on the hybrid servers using the activation codes and activation IDs obtained. Register the servers or virtual machines on-premises to the AWS Systems Manager service. In the SSM console, the hybrid instances will show with an mi- prefix. Apply the patches using the Systems Manager Patch Manager.
3. Download and install the SSM Agent on the hybrid servers using the activation codes and activation IDs obtained. Register the servers or virtual machines on-premises to the AWS Systems Manager service. In the SSM console, the hybrid instances will show with an i- prefix. Apply the patches using the Systems Manager State Manager.
4. Set up a single IAM service role for AWS Systems Manager to enable the service to execute the STS AssumeRole operation. Allow the generation of service tokens by registering the IAM role. Use the service role to perform the managed-instance activation.
5. Download and install the SSM Agent on the hybrid servers using the activation codes and activation IDs obtained. Register the servers or virtual machines on-premises to the AWS Systems Manager service. In the SSM console, the hybrid instances will show with an i- prefix. Apply the patches using the Systems Manager Patch Manager.

# Explanation
You only need a single IAM service role that can execute the STS AssumeRole operation (not several roles, and not AssumeRoleWithSAML) to perform the managed-instance activation. After installing the SSM Agent on the hybrid servers and registering them, the hybrid instances appear with an mi- prefix (not i-) in the SSM console, and patches are applied with Systems Manager Patch Manager. State Manager is only a configuration management service and is not used to apply patches.
