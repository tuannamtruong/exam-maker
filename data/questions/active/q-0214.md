# Scenario
A company has developed a serverless application that processes user requests using Lambda. The Lambda functions are designed to connect to an Aurora PostgreSQL database cluster for data retrieval and storage. Initially, the functions connected directly to the Aurora cluster, but this approach led to connection timeouts due to the high volume of short-lived connections generated by the Lambda functions. The DevOps engineer must consider a scalable and higher-performance solution.

# Question
What combination of steps should the engineer do in the following options to meet these requirements? (Select THREE.)

# Options
1. Configure the Lambda function to connect to the RDS Proxy endpoint.
2. Utilize ElastiCache to cache query results and decrease the direct read operations from the Aurora database.
3. Implement RDS Proxy to manage database connections, connect them to the Aurora cluster's reader and writer endpoint, and set a maximum connection threshold.
4. Optimize the SQL queries within the Lambda function.
5. Increase the memory and timeout settings of the Lambda function to handle higher throughput.
6. Integrate database connection pooling within the Lambda function's code and set the number maximum connection of database connections pool.

# Explanation
Database connection pooling refers to the practice of establishing and managing a pool of database connections that can be reused across multiple clients and requests instead of opening a new connection for each request.

Even if connections are long-lived, an application-side pool can optimize connection usage and ensure they are retrieved and returned quickly between queries for workloads with frequent open/close activity. Pools also make it easier to centrally configure connection properties for all database clients.

RDS Proxy is the managed implementation of it — maintaining the pool across Lambda invocations, enforcing max connection limits, throttling to protect the cluster.
