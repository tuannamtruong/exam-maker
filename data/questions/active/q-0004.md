# Scenario
A company needs to capture detailed information of all HTTP requests that went through its public-facing ALB every five minutes. The client's IP address and network latencies must also be tracked, while the load balancer's availability is monitored separately through the ELB health check. The captured data should be used for analyzing traffic patterns and for troubleshooting Docker applications orchestrated by the Amazon ECS Anywhere service.

# Question
Which option has the LEAST amount of overhead?

# Options
1. Enable AWS CloudTrail for their ALB. Use the CloudTrail Lake to analyze and troubleshoot the application traffic.
2. Enable access logs on the ALB. Integrate the ECS cluster with Amazon CloudWatch Application Insights to analyze traffic patterns and simplify troubleshooting.
3. Install and run the AWS X-Ray daemon on the ECS cluster. Use the Amazon CloudWatch ServiceLens to analyze the traffic that goes through the application.

# Explanation
ALB access logs capture detailed HTTP request information including client IP and latencies. CloudWatch Application Insights then analyzes traffic patterns with minimal overhead. CloudTrail tracks API/account activity, not HTTP traffic. X-Ray + ServiceLens won't capture client IPs unless ALB access logs are enabled.
