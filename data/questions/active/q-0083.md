# Scenario
system that should automatically send all AWS-scheduled maintenance notifications to the Slack channel. notify their IT Operations team if there are any AWS-initiated changes to their EC2 instances and other resources.

# Question
EASIEST method?

# Options
1. Use a combination of AWS Health and CloudWatch Events to track the AWS-initiated activities to your resources. Create an event using CloudWatch Events which can invoke a Lambda function to send notifications to the company's Slack channel.
2. Use a combination of Config and Trusted Advisor to track any AWS-initiated changes. Create rules in Config which can trigger an event that invokes a Lambda function to send notifications to the company's Slack channel.
3. Use a combination of EC2 Events and CloudWatch to track and monitor the AWS-initiated activities to your resources. Create an alarm using CloudWatch Alarms which can invoke a Lambda function to send notifications to the company's Slack channel.
4. Use a combination of Support APIs and CloudTrail to track and monitor the AWS-initiated activities to your resources. Create a new trail using CloudTrail which can invoke a Lambda function to send notifications to the company's Slack channel.

# Explanation
AWS Health provides ongoing visibility into the state of your AWS resources, services, and accounts, including AWS-initiated activities and scheduled maintenance. You can track these events with CloudWatch Events, which can invoke a Lambda function to push notifications to the company's Slack channel.

2. Config is not capable of tracking any AWS-initiated changes or maintenance in your AWS resources.
3. Although the use of CloudWatch is acceptable, especially CloudWatch Events, it is still invalid to use EC2 Events to track AWS-initiated activities. A better combination should be AWS Health and CloudWatch Events.
4. An integration of Support API and CloudTrail will not be able to properly monitor the AWS-initiated activities in your resources since CloudTrail simply tracks all of the API events of your account only but not the AWS-initiated events or maintenance.
