# Scenario
Control Tower landing zone. The DevOps team has set the identity store within IAM Identity Center (Single Sign-On) to external identity provider (IdP) and has configured SAML 2.0. principle of least privilege. The model must allow the team to build and manage only the team's own resources.

# Question
(Choose three.)

# Options
1. Create IAM policies that include the required permissions. Include the aws:PrincipalTag condition key.
2. Create permission sets. Attach an inline policy that includes the required permissions and uses the aws:PrincipalTag condition key to scope the permissions.
3. Create a group in the IdP. Place users in the group. Assign the group to accounts and the permission sets in IAM Identity Center.
4. Create a group in the IdP. Place users in the group. Assign the group to OUs and IAM policies.
5. Enable attributes for access control in IAM Identity Center. Apply tags to users. Map the tags as key-value pairs.
6. Enable attributes for access control in IAM Identity Center. Map attributes from the IdP as key-value pairs.

# Explanation
External IdP -> SAML attributes -> IAM Identity Center -> Attribute mappings -> Principal Tags -> Permission Set Policy -> AWS Resources

2-> With IAM Identity Center you do not normally attach IAM policies directly to users. Instead: Permission Set --> Creates IAM Role. The inline policy belongs inside the Permission Set.
3-> When using an external IdP, group already exist there. Users are added to those groups. IAM Identity Center synchronizes them. Then you assign them Group -> AWS Account + Permission Set
6-> This is the key feature. It maps SAML attributes from the IdP into AWS principal tags. Department=Finance -> aws:PrincipalTag/Department

1. In Identity Center, you use permission set, not IAM Policy.
4. You cannot assign Identity Center groups to OUs. OUs are only organizational containers in Organizations.
5. Because the identity source is an external IdP. You do not manually tag users inside IAM Identity Center. Instead, you map attributes coming from SAML.
If the situation is internal IdP, it would be correct.
