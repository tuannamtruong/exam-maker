# Scenario
The company currently uses:
CodePipeline
CodeBuild for build, test, and deployment

They now want:
CodeBuild only for build/test
CodeDeploy for deployment
The application is packaged as an RPM
Deployment target is an EC2 Auto Scaling group
All EC2 instances are launched from a common AMI

# Question
TWO

# Options
1.	Create a new version of the common AMI with the CodeDeploy agent installed. Update the IAM role of the EC2 instances to allow access to CodeDeploy. 
2.	Create a new version of the common AMI with the CodeDeploy agent installed. Create an AppSpec file that contains application deployment scripts and grants access to CodeDeploy. 
3.	Create a CodeDeploy application. Configure an in-place deployment. Specify the Auto Scaling group. Add an EC2 Image Builder step to CodePipeline to create a new AMI. Configure CodeDeploy to deploy the AMI. 
4.	Create a CodeDeploy application. Configure an in-place deployment. Specify the Auto Scaling group. Update CodePipeline to use the CodeDeploy deployment action. 
5.	Create a CodeDeploy application. Configure an in-place deployment. Specify individual EC2 instances as the deployment target. Update CodePipeline to use the CodeDeploy deployment action.

# Explanation
Every EC2 instance that receives deployments must run the CodeDeploy agent.
Since all instances are launched from a common AMI, the best practice is to bake the agent into the AMI so every new instance is ready for deployments.
The EC2 instance profile also needs permissions so the agent can communicate with CodeDeploy and retrieve deployment bundles.

2. An AppSpec file does not grant permissions.
3. CodeDeploy deploys application revisions, not AMIs.
